# G0–G8 交付质量门

> 所有门先应用 [当前制作配置](current-production-profile-v3.md)。本文件只保留活动质量门；历史条款见 CHANGELOG。

本文件用于完整制作、跨节点制作、草稿复核和最终交付。执行时按顺序推进；前一门未通过，不得把后一节点的产物描述为完成。定向修改只执行受影响的门，但最终仍须重新执行 G5–G8。

## 状态词

- `BLOCKED_SOURCE`：事实、来源、精准查询或素材身份不合格。
- `BLOCKED_VISUAL`：原文字、黑边、封面、构图或画面身份不合格。
- `BLOCKED_AUDIO`：响度、真峰值、混音差值或尾音不合格。
- `BLOCKED_TIMELINE`：实际帧数、字幕块、首尾帧或音画长度不合格。
- `DRAFT_READY`：事实、素材、预览和草稿门通过，可以交用户评审，但尚未完成最终编码验收。
- `FINAL_READY`：最终 MP4 的事实、视觉、声音、时间轴和交付记录全部通过。

只有 `FINAL_READY` 可以使用“已完成”或“最终版”表述。任何 `BLOCKED_*` 都要给出失败项、证据和下一步，不能用文字版“通过报告”覆盖实际问题。

## G0｜环境与工程门

- 按 [environment-setup.md](environment-setup.md) 完成所需工具预检；首次在新机器或升级后运行 `scripts/smoke_test_brief_pipeline.py`。
- 每个主题使用独立工作目录；原素材只读，清理版、草稿、候选最终版和验收文件分离。
- 工作文件放在 `<项目根>/.news-editor-work/YYYY-MM-DD/N.中文新闻短名/`，不得把下载素材、脚本、截图、缓存、工程、预览或 QA 文件直接写入输出区（根目录见 `config.json` 的 `output.root`）。
- 输出目录固定为 `<输出根>/YYYY-MM-DD/N.中文新闻短名/`。只有通过 G0–G8 的 `FINAL_READY` 文件才能进入输出目录。

必需项失败时停在受影响节点，不在渲染中途反复试错。

## G1｜事实与来源门

- 核心事实至少通过两个相互独立的可靠来源交叉核验；存在政府、企业、机构或当事方原始发布时必须纳入。
- 国家级媒体及其转载、聚合署名和平台账号不作为候选新闻来源、事实来源、交付链接或剪辑素材来源。政府部门、法院、警方、企业/机构公告和当事方原始发布不属于此排除项。
- `fact-pack.md` 区分已证实事实、推断/传闻、不可写入内容，并记录标题、链接、发布日期和事件日期。
- 锁定合格非国家级报道页面的完整 `canonical_source_title`。
- 选题红线逐条留证：有信源、改写度足够、时间没有错位。

事实不足、来源身份不明或核心数字冲突时状态为 `BLOCKED_SOURCE`，禁止进入素材下载。

## G2｜精准检索与下载门

- 第一条抖音查询使用规范化后的完整 `canonical_source_title`；只允许删除标点、话题符号和无信息量前后缀。
- 在 `source-manifest.md` 同时记录原始标题、规范化标题、实际首条查询和两者一致性结论。
- 每个主题准备 1–5 条可解码视频（上限见 config），合计可用时长覆盖成片；记录视频 ID、规范化页面 URL、账号、平台标题、本地文件、媒体规格、哈希和候选时间码。另行准备 config 指定数量的封面候选（独立高清图片优先，其次原片清晰关键帧），并为每个制作无标题 3:4 底图、270×360 无标题缩略图和候选接触表。可补充少量可追溯图片或事实信息截图，但不得用它们替代全部视频，除非已确认走纯图文形态。
- 下载前必须打开规范化视频页，记录候选与原始标题属于同一事件的具体证据；下载后必须完整解码验证。
- 首轮不足时，只能在完整标题后增加地点、主体或“现场”等限定词；不能退化成宽泛关键词。
- 若精确标题结果全部是主播、AI 主播、对镜口播或单一人脸近景，必须从 `fact-pack.md` 的受影响人群、地点、动作和办理流程生成 `scene_queries`，并登记为资料画面。

首条查询不一致、无法追溯或没有合格素材且信息不适合纯图文形态时状态为 `BLOCKED_SOURCE`。

## G3｜素材身份与相关性门

每个候选片段必须记录：

- `subject_identity`：画面中的具体人物、产品、地点或事件。
- `footage_type`：`direct_event`、`official_product`、`archive`、`test`、`render`、`patent_diagram` 或 `unrelated`。
- `supports_claim`：该镜头能够支持的正文字幕块。
- `misleading_risk`：是否可能被误认为新闻现场、真机或已确认信息。
- `original_text_regions`：顶部、中部、底部文字与动态变化情况。
- `usable_timecodes`：源入/出点、可用秒数和支持的字幕块。
- `target_crop`：最终实拍带的裁切、缩放、位移，以及需要时的精确模糊框与生效时段。
- `footage_role`：`direct_evidence`、`contextual_broll` 或 `first_hand_quote`。
- `scene_category`：例如事件现场、机构/政策、家庭/照护、办理流程。
- `face_dominant`：按最终裁切后人物脸部是否占据主要视觉面积判断，并记录预计使用时长。

硬性规则：

- `unrelated` 直接淘汰；其他产品、其他人物或其他事件不得替代新闻主体。
- `archive`、`test`、`render`、`patent_diagram` 只能在确实支持正文且不会造成身份误导时作为辅助画面。
- `contextual_broll` 只能说明受影响人群、生活场景或办理流程，不得冒充事件现场、当事人或事实来源；只要时间轴里出现资料画面，片头就必须有免责小字。
- `first_hand_quote` 必须是当事方或目击者原话，字幕逐句对照事实包；只有它可以保留源字幕与原声。
- 主播、主持人、演播室口播者、AI 播报人员和对镜口播片段不得进入最终时间轴，也不得作为封面。普通人物 `face_dominant=true` 的单段最长 1.5 秒，合计不超过正文画面的 20%。
- 评论截图浮层最多一个（时长见 config），只作讨论氛围；字幕与标题不得把评论内容写成事实。
- 无法取得相关、可清理、可铺满实拍带的画面时，返回 G2 或更换选题；不用无关画面或生成画面补足。

任一实际使用镜头身份不一致时状态为 `BLOCKED_SOURCE`。

## G4｜清理、构图与预览门

渲染全片前，必须生成并实际查看：

- 封面预览；封面全部候选的无标题 3:4 底图、270×360 无标题缩略图与同尺寸接触表。
- 封面中央 3:4 区域缩放到 270×360 的双列信息流缩略图。
- 每个实际使用片段在最终实拍带下的开头、中间和结尾帧。
- 每个镜头切点前后各一帧。
- 每个字幕块的定格图与滑入过程帧。
- 标题区包装层与平台叠层预览。

预览必须满足：

- 除已核对的当事方原话片段外，顶部/中部/底部原始文字为零；允许的底部字幕局部模糊全程不可辨认、范围稳定且不遮挡主体。
- 封面零字幕、零水印、零模糊、零马赛克；来源是独立高清图片或原片清晰关键帧，几何门通过并留证。原图、无标题底图、无损母版在 100% 下没有失焦、拖影或明显压缩损伤。
- 封面候选的四项人工评分分别达到 config 单项门槛，总分达到 config 总分门槛，评分有实际预览路径和逐项依据。
- 封面主副标题各一行，字号在配置上下限之间，字宽不超过硬上限；不得横向压缩或换行。
- 270×360 缩略图无需放大即可先辨认真实主体或场景，再读清两行标题。
- 实拍带四边连续被已登记的有效素材填满，无黑边、黑带、空白或手工补边；背景为素材模糊副本。
- 标题块 2–3 行、末行黄色斜体，每行独立成句且在锁定宽度内；结果行为独立红字行；资料画面带免责小字；来源媒体名不出现在标题块和结果行。
- 字幕块为黄色黑边斜体、居中、不超过 4 行与锁定宽度；无错字、无叠影。
- 草稿必须运行 `scripts/extract_layout_proof.py` 并逐张查看 `cover / header / footage(或 panel) / caption / cut / final`；任一分板缺失、未查看或边界偏离锁定计算超过 2px，状态为 `BLOCKED_VISUAL`。
- 封面和正文均不出现“资料画面”“素材：抖音@xxx”等素材账号说明；免责小字使用锁定文案。

平均亮度、颜色像素数量或“存在画面”不能证明视觉合格。失败时状态为 `BLOCKED_VISUAL`。

## G5｜最终时间轴门

- 正文实拍带与字幕区的边界由锁定 JSON 和当前文案堆叠计算；封面几何单独执行 config 的放大倍率上限，正文片段执行锁定 JSON 的 `media_quality`；两者均须人工确认没有明显失焦、压缩块或运动模糊。
- 含静态素材的时间轴须确认 render 报告的 `still_motion_supersample` 不低于 config `video.still_media.motion_supersample`。
- `timeline.json` 通过 `production_contract.py`：字幕块从第 1 帧起连续覆盖全片；每块停留不低于声明的阅读下限，且声明值不低于 config 的阅读公式；素材片段连续覆盖全片；`timing` 记录完整；`edit-plan.md` 保留编辑判断。
- 总时长在 config 的快讯区间内；超区间时有明确的延长授权记录，且不超过硬上限。
- 对最终编码 MP4 使用完整解码或 `ffprobe -count_frames` 取得实际帧数；必须与 `total_frames` 完全相等，禁止用“容器时长 × 帧率”推算。
- 抽查第 0 帧、第 1 帧、每个字幕块到达帧、每个镜头切点前后、最后三帧。第 0 帧为封面，第 1 帧直接进入正片。
- 视频与音频尾部都须完整，误差不超过一帧；较长音轨不得掩盖视频尾部缺帧。
- 每个字幕块在手机尺寸静音播放时读得完；未做此复核记录 not_checked。

机器验收命令：

```powershell
python scripts/validate_news_video.py <final.mp4> --timeline <timeline.json> --assembly-report <assembly.json> --qa-dir <qa/frames> --qa-frames auto --report <qa/qa-report.json>
```

失败时状态为 `BLOCKED_TIMELINE`。

## G6｜最终声音门

- 放行测量对象必须是最终编码 MP4；中间 WAV 只能用于调试。
- 默认最终音频为 AAC、48kHz、立体声。
- 综合响度与真峰值按时间轴声明的音频模式，落在 config `mix.loudness_targets` 对应模式的区间与上限内。
- `original_bgm` 与 `tts_bgm` 模式：每个突出音频区间分别测量人声轨与 BGM 轨，BGM 比人声低 config 规定的分贝数，容差见 config。
- 原声或配音须在对应区间内完整结束，无截尾、爆音、削波或原素材人声争抢；原声片段逐句试听并与字幕核对。

只检查“存在音轨”不能通过本门。失败时状态为 `BLOCKED_AUDIO`。

## G7｜最终视觉与事实门

必须从最终 MP4 重新抽帧，不沿用渲染前预览结论。以下任一情况一票否决：

- 任一检查帧出现未经许可的可辨识源字幕、标题条、日期条或说明文字（已核对的当事方原话片段除外）。
- 底部字幕模糊后仍可读，或模糊区域遮挡主体。
- 封面存在任何模糊、马赛克、修补或遮字；封面来自播放器截图、平台缩略图或成片反抽帧；实际上传文件与验收文件哈希不一致。
- 封面缺少无标题候选接触表、四项人工评分或逐项依据；任一项未达 config 门槛。
- 已知平台“封面模糊或拉伸”告警尚未解决；按 [封面告警恢复流程](cover-platform-layout-v3.md) 留证并修复。未授权上传时不擅自上传，平台状态记录为 `not_checked`。
- 实拍带存在大块黑边、黑带、空白或手工补边。
- 封面出现主播、源文字、无关主体，或只剩标题、框线和纯黑空底。
- 标题块不是 2–3 行混排、末行不是黄色斜体，或缺少应有元素。
- 标题块或结果行出现新闻来源媒体名、记者或账号信息；右下角缺少来源小字。
- 时间轴使用资料画面却没有免责小字；字幕或标题把资料画面、评论截图当成事实来源。
- 最终时间轴出现主播、AI 主播或对镜口播；人脸主导片段合计超过正文画面的 20%。
- 字幕块滑入过程闪烁、叠影、半途停住，或在到位前出现。
- 画面中的人物、产品、地点或事件与正文身份不一致。
- 源视频文字带入未经核验的新事实、数字或推测。

最终视觉失败时状态为 `BLOCKED_VISUAL`；事实身份失败时状态为 `BLOCKED_SOURCE`。

## G8｜交付完整性门

逐块突出音频（原声或配音）的原始轨必须可解码并完成人工听检；最终音轨只含 BGM、明确保留的原声和用户要求的配音。`qa-report.json` 记录音频模式、BGM 文件与哈希、（配音时）model、voice_id、文本哈希、trace_id、人工听检区间和 `platform_voice_policy_review=manual_required`，不得记录 API Key。最终 MP4 basename 必须与人工核对的完整封面标题（封面主标题 + 全角逗号 + 封面副标题）逐字一致，并以主题目录去掉 `N.` 后的封面主标题开头。

每个完整主题至少包含：

- `fact-pack.md`
- `source-manifest.md`
- `edit-plan.md`
- 封面 PNG 与代表性预览帧
- 270×360 封面缩略图与平台叠层预览帧
- 最终 MP4
- `qa-report.json`

`qa-report.json` 必须保存文件哈希、实际解码帧数、总时长、字幕块帧区间、视频流/容器时长、宽高、帧率、音频采样率与声道、音频模式、最终 LUFS/TP、（有突出音频时）各区间差值、实际查看的帧号、使用素材与时间码及角色、每段目标裁切/缩放/位移与模糊框/时段、`footage_role`、`face_dominant`、封面来源类型与（关键帧时）时间码、封面原图/无标题底图/无标题缩略图/候选接触表路径与哈希、四项人工评分及逐项依据、封面两行字宽与实际字号、免责小字检查、平台安全区检查、最终 `layout-proof.json` 路径与所有分板实际查看结论，以及每个硬门的结构化结果。数值必须来自命令输出，视觉布尔值与人工评分必须对应实际保存并查看的预览，不能手工按目标值填写。

素材清单和交付文档不得记录浏览器 profile 绝对路径、登录态有效期、Cookie、会话 ID、临时签名链接或其他运行时凭据。

所有门通过后把状态写为 `FINAL_READY`，再执行输出：每个主题的输出目录默认只保留一个稳定中文名 MP4 和一个 `封面.png`；日期目录按生产顺序从 `1.` 连续编号。运行 `scripts/check_output_layout.ps1`（输出根目录缺省从 config.json 读取）后必须通过目录结构检查。发布时 `acceptance.json.review` 还必须明确 `muted_reading=passed` 与 `voiced_playback=passed`；未执行记录 not_checked。执行脚本与证据结构见 [可执行制作链路](executable-production.md)。事实、四时间、表达与当前工件还须通过[编辑记录门](editorial-feedback-loop.md)。
