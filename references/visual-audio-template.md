# 资讯快讯视觉、字幕节奏与声音模板

> 新制作先执行 [当前制作配置](current-production-profile-v3.md)。本文件只保留活动规范；被取代的分页版式与强制配音规则见 CHANGELOG。

本模板用于用户没有另行指定视觉或声音方案的新闻短视频，依据是账号四条高播放成片的逐帧实测。制作封面、字幕块、音频模式或最终视觉验收前读取本文件，并按需检查对应参考资产。用户当次明确要求优先于本模板；参考资产中的示例文案和合成画面只用于观察样式，不得复制到其他新闻成片中。

- [参考接触表](../assets/references/v3-reference/reference-contact-sheet.png)：三行依次是三行标题块的视频形态、两行标题块（白字首行）的视频形态、纯图文形态；每行给封面、字幕稳定帧和末帧。
- [字幕滑入逐帧](../assets/references/v3-reference/caption-slide-in-strip.png)：字幕块 6 帧滑入的拖尾形态。
- [标题与字幕细节](../assets/references/v3-reference/typography-detail.png)：四种标题行样式、结果行、免责小字、字幕、纯图文正文高亮和封面文字的放大细节。

对标用的四条账号成片原件不随仓库分发（含第三方画面）。四种题型的做法：政策时间表等没有素材的信息用纯图文版（`brief_text`）；判决、纠纷类用三行标题块＋红字结果行，全部为资料画面时加免责小字；暖闻、现场类用两行标题块＋现场素材，讨论氛围可用评论截图浮层；有当事方原话的保留源字幕与原声。修改版式、渲染器或示例文案后，在 Windows 上重跑 `build_layout_reference.py`，核对并提交这三张图。

封面沿用既有参考资产（样式未变）：[封面完整样式](../assets/references/cover-style-reference.png)、[封面文字与装饰](../assets/references/cover-typography-reference.png)、[V3 透明四角框与手绘线](../assets/references/cover-frame-lines-v3.png)、[封面双列缩略图正反例](../assets/references/cover-grid-good-bad-reference.jpg)、[平台叠层参考](../assets/references/platform-overlay-reference.webp)。旧版分页成片的资产已归档到 `assets/legacy-v2/`，只供回看旧成片，不再作为制作依据。

## 成片结构

画布、帧率与全部坐标以 `config.json` 的 `layout` 段引用的锁定 JSON 为准（人读镜像见 [锁定版式与分区验收](locked-layout-validation.md)）。本文件不复述数值。

- **第 0 帧是封面**，第 1 帧直接进入正片；封面只占这一帧。
- **`brief_video`（视频形态）**自上而下为：标题块（2–3 行混排，可选 1 行红字结果行，可选资料画面免责小字）→ 实拍带（全宽，由真实素材等比铺满）→ 字幕块（黄色黑边，压在模糊背景上）。实拍带上下之外的画面由渲染器用当前素材的模糊副本自动填充，并随镜头切换同步变化。
- **`brief_text`（纯图文形态）**：蓝色渐变背景缓慢下移，1 行黄色斜体标题，半透明深色面板内逐行出现白色正文，关键词用黄字高亮，各行累加保留到片尾。
- 画面右下角固定有来源小字（`source_label`），媒体名不进入标题块和结果行。
- 平台叠层关系：详情页顶部标题栏可能盖住标题块第 1 行，右侧操作栏与底部标题/评论区会压到画面边缘。因此标题块每一行都要能独立成句，关键事实不得只出现在第 1 行；字幕块宽度不超过锁定值，避免长行伸进右侧操作栏。

## 标题块与结果行

标题块承担“一眼看懂”，不照抄发布标题：

- 2–3 行，每行不超过 config 的标题行字宽；顺序是“背景或反常点 → 核心事实 → 反转或细节”，**末行固定为黄色斜体**（`yellow_italic`），承载反转、辩解或细节。
- 可用样式：`yellow_tag`（黄底黑字）、`black_tag`（黑底黄字）、`yellow_italic`、`white_italic`（白字黑边，通常作首行）。同一标题块内不重复同义内容。
- 结果行（`result_line`）可选，1 行红字白边，写判决、回应或落地时间等“结论”；没有明确结论时不写。
- 纯图文版的标题是 1 行黄色斜体，概括整个更新。

## 字幕块、字数与节奏

字幕承载全部信息（默认不配音），所以它必须自己读得通：

1. 3–4 个字幕块（数量与总字数区间见 config `video.copy_limits`），每块 1–4 行，每行不超过 config 的字幕行字宽；每块只讲一个信息点，块内按语义断行，不拆开人名、机构、日期、数字单位和否定关系。
2. 第一块直接给最重要的事实（谁、发生了什么）；事件类后续块依次给回应/结果/影响，政策类给条件/时间/怎么办。已知回应或结果不故意留到最后。
3. 每块停留不低于 config 的阅读下限：`reading_base_seconds + reading_per_unit_seconds × 字宽数`，且不小于最小块时长。这是机器下限，来自样片实测（每块约 2.4–4.5 秒）；数字多、条件多时编辑应再加长。
4. 总时长由各块相加得出，通常 9–13 秒。装不下先删重复信息；仍需延长须取得用户授权，且不超过硬上限。不靠拉长停留凑时长。
5. 纯图文版每行按固定节奏逐行出现（间隔见 config `video.timing`），最后一块完整显示后至少停留 config 规定的收尾时长。
6. 汉字和全角符号计 1 个字宽，ASCII 字母数字约 0.55；计数只是预筛，渲染器会按真实字形宽度在锁定宽度内自动适配字号（不低于下限），低于下限仍放不下必须改写。
7. `edit-plan.md` 在渲染前写明：每个字幕块的信息任务、阅读依据、最低停留与到达帧，以及每段素材的入/出点、支持的字幕块、裁切与源文字处理。

## 固定字体与颜色

- 全片使用微软雅黑粗体，运行时用 `Join-Path $env:WINDIR 'Fonts\msyhbd.ttc'` 定位并通过 `--font` 传给渲染器；字体缺失时停止，不静默替换。
- 标题块、结果行与字幕一律右倾斜体（斜切量见锁定 JSON），标签行为平行四边形；纯图文版正文正立。
- 颜色只取锁定 JSON 的 `colors` 段：标题黄、封面青、白、黑、结果行红、来源灰、纯图文背景渐变与面板透明度。
- 字号、描边、加粗补偿、标签内边距与行距全部由锁定 JSON 决定；渲染器按锁定宽度自适应字号，超出下限即报错，不横向压缩。

## 实拍带与背景

- 实拍带顶边由锁定 JSON 与当前文案堆叠决定：标题块自固定底边向上堆叠，不改变顶边；带结果行或免责小字时实拍带变矮。时间轴检查会据此计算区域，渲染与分板使用同一结果。
- 素材按 `crop` 选定区域后等比放大铺满实拍带，焦点随主体移动；禁止 `contain` 黑边、黑带、空白或手工模糊补边。
- 背景是整帧源画面铺满画布后的强模糊副本，由渲染器生成；不需要也不允许手工制作背景。
- 源字幕、标题条、日期条和大面积文字通过换时间段、裁剪或移动焦点移出实拍带；底部字幕裁不掉且裁剪会伤害主体时，可对实际字幕框做局部强模糊使其完全不可辨认。只有已核对的当事方原话片段（`first_hand_quote`）允许保留源字幕。
- 镜头之间硬切，不叠加转场；避开源素材自带的叠化、重影或模糊帧。单段通常 1.6–5 秒（见 config `video.footage`），不为凑时长重复同一时段或变速。
- 图片、信息截图与文字材料截图合计不超过 config 限额，带连续克制的缩放或平移；评论截图只作浮层，不作事实来源。

## 字幕滑入动画

- 每个字幕块从右侧滑入，6 帧（30fps 下 0.2 秒）内减速到位，带方向性运动模糊：前缘实、拖尾淡；到位后静止到下一块到达。
- 视频形态里新块到达时旧块同步向左滑出；纯图文版只进不出，逐行累加。
- 字幕在它对应的信息开始被“读”的那一刻到位：默认模式下首块在开场延迟后到位，其余块在各自起始帧到位；配音模式下在对应配音起点到位。
- 验收时逐帧查看每个到达帧：不得提前出现、闪烁、叠影或停在半途。

## 封面版式

封面沿用既有样式，详细执行 [封面与平台安全布局](cover-platform-layout-v3.md)，以下为硬性摘要：

- 第 0 帧即封面：画面区内是单独检索的高清图片，或已下载原片里清晰且无源文字的关键帧；两种来源都零字幕、零水印、零模糊、零马赛克。
- 直接叠加透明 `cover-frame-lines-v3.png`；青色主标题与白色副标题保持单行，字号以锁定上限为起点、按文字宽度自适应到下限，超过字宽硬上限必须改写文案。
- 四项人工编辑门（技术清晰、主体可辨、主题高度相关、视觉冲击）逐项达标，并过几何门；无标题 3:4 底图与 270×360 缩略图中主体仍清晰可辨。
- 封面不得出现播报人员、资料画面说明或素材账号；独立上传的 `封面.png` 是封面母版的 3:4 区域无损导出。

## 音频模式

模式由时间轴 `audio_mode` 声明，默认值与各模式的响度目标见 config 的 `audio` 与 `mix` 段：

- **`bgm_only`（默认）**：只有 BGM，观众读字幕。BGM 从内置曲库按题材情绪选择并在 `edit-plan.md` 记录实际文件（政策/实用类明快，案件/严肃类克制，暖闻类抒情）；加短淡入淡出；整体响度对齐样片实测目标。不需要任何 TTS 凭据。
- **`original_bgm`**：当事方原话本身是新闻时使用。仅在 `first_hand_quote` 片段保留原声，原声按人声目标响度归一，BGM 在原声区间压低 config 规定的分贝数，区间外回到独奏电平。原声片段必须有清晰的语音，嘈杂或听不清的原声改用默认模式。
- **`tts_bgm`**：仅在用户明确要求配音时使用。逐字幕块生成 MiniMax 配音并实测时长，字幕随配音到位；凭据停点与参数见 [MiniMax TTS 集成](minimax-tts.md)，逐块试听人名、数字、否定词与多音字。
- 下载素材的原声在其余片段一律静音；最终音频为 AAC、48kHz、立体声，响度与真峰值按当前模式的目标在最终 MP4 上实测。

## 模板验收

- 按时间轴声明核对：总帧数、字幕块区间、封面只占第 0 帧；最终 MP4 实际解码帧数等于计划。
- 对封面、270×360 双列缩略图、每个字幕块到达帧、每个镜头切点前后帧、滑入过程帧和平台叠层预览抽帧，与对标参考资产比较字体观感、颜色、层级、倾斜、描边与安全边距。
- 标题块末行为黄色斜体；来源小字在右下角来源安全框内；资料画面带免责小字。
- 分板脚本拆出的封面、标题区、实拍区（或面板）、字幕区全部实际查看，边界与锁定 JSON 偏差不超过容差。
- 对最终编码 MP4 机器测量综合响度与真峰值，按当前音频模式的目标判定；`original_bgm` 与 `tts_bgm` 另测每个突出音频区间与 BGM 的差值。
