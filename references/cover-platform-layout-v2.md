# 封面与平台安全布局 V2

> **当前覆盖规则**：先执行 [当前制作配置 V2](current-production-profile-v2.md)。尤其是封面零模糊/零马赛克，以及 `layout-lock-v2.json` 的正文坐标；下文冲突的旧规则只作历史参考。

本文件用于制作封面、正文布局和发布前平台预览。用户没有明确指定其他版式时，必须执行本文件；用户只改变其中一项时，其他参数保持不变。

## 2. 封面文案不是新闻长标题

封面承担缩略图点击识别，不复述完整报道标题。先从事实标题中提炼两层信息：

- `cover_headline`：主体或最强事件钩子，理想 4–7 个全角字宽，硬上限 8。
- `cover_subline`：结果、场景或第二信息点，理想 5–10 个全角字宽，硬上限 12。
- 两行合计硬上限 18 个全角字宽；同一事实不得在两行重复。
- 汉字和全角符号计 1；ASCII 字母或数字计 0.55；半角标点计 0.5。计数只是预筛，最终必须以实际字体测量宽度为准。
- 主标题不写完整日期、来源名称和“发布/宣布/回应称”等弱信息前缀，除非日期本身就是新闻钩子。
- 禁止通过减小字号容纳长文案。超过宽度时必须重新压缩文案。

通过示例：

```text
苹果新CEO
首场发布会

机器人闪电
百米8秒94再破纪录
```

失败示例：

```text
小鹏机器人融资超9亿美元
腾讯、阿里参与战略投资

小米玄戒三芯齐发
手机到智驾全栈AI算力
```

失败原因不是事实错误，而是字数过多迫使字号缩小，在双列信息流中失去第一视觉层级。

## 3. 封面合成顺序

画布固定为 1080×1920，合成顺序不可颠倒：

1. 从已下载视频选择与事件直接相关的干净帧。
2. 每个候选帧先保存未处理版本，再裁掉源画面内部黑边、标题、字幕、日期条、账号贴纸和说明文字。
3. 将有效画面按 `cover` 等比例铺满锁定 JSON `cover.background_video` 的区域，根据主体移动焦点；不得拉伸。必须先尝试换帧、裁切和焦点位移，不能先用模糊掩盖构图问题。
4. 只有换帧和构图后仍残留、且确实属于原素材文字的局部区域允许精确模糊。模糊框应紧贴文字，逐帧跟随动态字幕；禁止把顶部、右侧或底部整块有效画面统一模糊。底部字幕横跨全宽时可以使用窄条局部模糊，但主体、动作和事件环境仍须清晰可辨；若有效信息被模糊掉，改用其他时间点或其他已下载素材。
5. 先在画布底层铺设深海蓝渐变（色值见锁定 JSON `colors` 段），再放置真实下载画面；将透明四角框资产（见 config.json `cover.frame_overlay`）以画布原尺寸叠加。禁止使用旧版不透明暗层覆盖画面。
6. 按本文件固定参数重新排版当前新闻的 `cover_headline` 和 `cover_subline`。`cover-text-layout-v2.png` 只能用于比对，不得直接叠加示例文字。
7. 导出独立 `cover.png`，再把它作为最终视频的第 0 帧；同时保存完整封面、270×360 缩略图和对应的未处理候选帧，作为验收证据。

禁止在封面出现：

- 新闻主播、演播室口播者、AI 播报人员；
- 源视频自带的任何可辨识标题、字幕、日期、账号贴纸或水印式说明；
- “资料画面”“素材：抖音@xxx”等素材说明；
- 第三方概念渲染、专利图或未确认真机；
- 与正文不同的产品、人物或事件。
- 纯黑或近似纯黑的整块背景、未显示可识别真实画面的空封面。

企业高管、当事人或事件主体本人可以出现，但必须是新闻主体，而不是负责播报新闻的人。

## 4. 封面固定排版

- 主标题：微软雅黑粗体 `144px`，行高 `158px`，颜色 `#0AEAE6`，水平居中；文字可见包围盒参考 `y=1140–1250`，安全宽度 `x=80–1000`；黑色描边 5–6px 或等效硬阴影。
- 副标题：微软雅黑粗体 `112px`，行高 `128px`，白色，水平居中；文字可见包围盒参考 `y=1309–1405`，安全宽度 `x=54–1026`；黑色描边 4–5px 或等效硬阴影。
- 主副标题必须各占一行，禁止换行、横向压缩、非等比缩放和自动缩字。
- 两行标题的视觉中心与参考资产一致。主体面部、产品核心部件或关键动作不得被标题遮住；构图冲突时换帧或移动背景焦点，不移动文字模板。
- 青色只能用于主标题；副标题保持白色。不要因为品牌色改成橙色、红色或其他颜色，除非用户当次明确要求。

## 5. 缩略图验收门

全尺寸封面通过不代表信息流缩略图通过。渲染全片前必须同时检查：

1. 完整 9:16 封面缩放到 270×480。
2. 中央 3:4 区域 `crop=1080:1440:0:240` 后缩放到 270×360，模拟双列信息流卡片。

在 270×360 预览中必须满足：

- 不放大图片也能立即读出两行文字；
- 主标题仍是第一视觉层级，宽度约占安全区域 55%–88%；
- 副标题清楚但不抢主标题；
- 两行均完整，没有触边、截字或缩成小字；
- 主体仍能被识别，文字没有压住主体关键部位；
- 四角框完整可见。
- 真实场景或主体清楚可辨，不得只剩标题、四角框和深色底板；封面 3:4 画面区内不允许出现占比超过 15% 的连续纯黑/近纯黑均匀空区。

任一项失败即 `BLOCKED_VISUAL`，先改文案或换底图，不进入全片渲染。

## 6. 正文平台安全布局

平台叠层会覆盖底部账号、发布标题、操作栏和评论入口。默认 1080×1920 采用以下保守安全区：

```text
白色正文安全区：锁定 JSON 的 white_copy_safe_bbox
红色强调允许区：锁定 JSON 的 red_emphasis_safe_bbox
右侧交互保留区：x=850–1080, y=700–1810
底部平台高风险区：x=0–1080, y=1790–1920
```

右侧和底部保留区可以继续显示无文字的实拍画面或非关键信息，但不得新增主副标题、白色正文、关键数字、页码或来源。红色强调行可以进入平台账号栏的垂直区间，并与左侧蓝色账号 Logo 轻微重叠；平台预览中至少 75% 红字面积和完整语义仍需可读。

默认正文页使用确认成片实测的锁定三段式结构，不使用浮动大信息卡；所有坐标、尺寸与色值以 [锁定版式 JSON](../assets/references/locked-layout/layout-lock-v2.json)（`config.json` `layout` 段引用）为唯一来源，本文不复述数值：

- 顶部标题区：深海蓝渐变底板（锁定 JSON `body_page.header`）。主标题为微软雅黑粗体、黄色、居中、单行（字号见同字段）；副标题条为 `subtitle_bar`，内部黑色粗体、单行。
- 黄色分隔线：`divider`；副标题与视频之间不得出现额外空隙。
- 实拍层：`body_page.footage`。真实下载素材按 `cover` 铺满，先裁出有效影像区再等比例放大和移动焦点；禁止 `contain`、黑边、空白或模糊复制背景。
- 正文区：全宽深海蓝渐变底板 `copy_board`。栏目角标 `section_label`、页码 `page_number_safe_bbox`；正文固定拆为 1–2 行白色说明与 1 行红色重点。
- 关键文字边界：白字 `white_copy_safe_bbox`、红字 `red_emphasis_safe_bbox`、来源 `source_safe_bbox`、底部黄线 `bottom_accent`；平台右侧保留区 `platform.right_reserved_*`（来源行除外）。
- 正文区可以延续到画布底部，但使用同一深海蓝渐变，不使用纯黑。除非用户当次明确指定，禁止恢复浮动大卡片、把实拍层压成狭小窗口，或以整幅模糊画面作为背景。

## 7. 平台叠层预览门

最终 MP4 交付前，从最终编码文件重新抽取：第 1 帧、每页中点、每个切点后 1 帧和末帧。把这些帧按 [平台叠层参考](../assets/references/platform-overlay-reference.webp) 的遮挡关系检查，或在目标平台的草稿预览中检查。

以下任一项直接失败：

- 白色正文、关键数字、来源或页码与账号头像、发布标题、右侧按钮、评论入口重合；红色强调行允许与左侧账号 Logo 轻微重叠，但被遮挡超过 25% 或语义无法完整阅读仍失败；
- 为避让平台 UI 把正文缩到手机端难以阅读；
- 正文越出白字/红字安全框，进入平台右侧保留区（锁定 JSON `platform` 段，来源行除外），或板块边界偏离锁定 JSON 超过容差（config.json `layout.tolerance_px`）；
- 平台预览后才发现文字被挡，却仍将文件标记为最终版。

平台界面可能变化；如果用户提供了新的平台截图，以新截图测量覆盖范围并扩大保留区，不能缩小本文件的默认安全区而不做实际预览。

## 8. 交付记录

`qa-report.json` 或视觉验收记录必须包含：

```json
{
  "cover_copy": {
    "headline": "<短主标题>",
    "subline": "<短副标题>",
    "headline_units": 0,
    "subline_units": 0,
    "font_sizes": [144, 112],
    "thumbnail_270x360_passed": true
  },
  "platform_safe_layout": {
    "white_text_bbox": [54, 1602, 820, 1707],
    "red_emphasis_bbox": [54, 1726, 820, 1770],
    "red_overlap_max_ratio": 0.25,
    "bottom_high_risk_from_y": 1790,
    "right_reserved_from_x": 850,
    "preview_frames": [],
    "passed": true
  }
}
```

这些布尔值必须对应实际保存并查看的预览帧，不得仅因为代码参数符合模板就填写为 `true`。
