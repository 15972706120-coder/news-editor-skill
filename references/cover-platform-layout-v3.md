# 封面与平台安全布局 V3

> 先执行 [当前制作配置](current-production-profile-v3.md)。本文件为活动规范；历史规则只保留在 CHANGELOG。封面零模糊/零马赛克，不适用正文的字幕清理例外。

本文件用于制作封面、安排正文与平台的相对位置、做发布前平台预览。封面样式自 V2 起没有变化，变化的是来源（允许原片清晰关键帧）与字号（按宽度自适应到下限）。用户没有明确指定其他版式时必须执行本文件；用户只改变其中一项时，其他参数保持不变。

## 2. 封面文案不是新闻长标题

封面承担缩略图点击识别，不复述完整报道标题。先从事实标题中提炼两层信息：

- `cover_headline`：主体或最强事件钩子，理想 4–7 个全角字宽，硬上限 8。
- `cover_subline`：结果、场景或第二信息点，理想 5–10 个全角字宽，硬上限 12。
- 两行合计硬上限 18 个全角字宽；同一事实不得在两行重复。
- 汉字和全角符号计 1；ASCII 字母或数字计 0.55；半角标点计 0.5。计数只是预筛，最终以实际字体测量宽度为准。
- 主标题不写完整日期、来源名称和“发布/宣布/回应称”等弱信息前缀，除非日期本身就是新闻钩子。

对标成片的封面用法：`12306 / 迎来重大更新`、`非洲婚礼 / 父亲送比亚迪当嫁妆`、`未婚情侣同居生子 / 分手后男方起诉100万`。8 个字的主标题会用到下限附近的字号，仍能保持第一视觉层级；超过硬上限则必须压缩文案。

## 3. 封面合成顺序

画布固定为 1080×1920，合成顺序不可颠倒：

1. **取得底图，两种来源按优先级**：
   - 优先：以新闻主体、地点、设备、动作或受影响场景为关键词，单独检索高清图片。优先原始发布方/机构媒体库、当事方公开图片和可追溯摄影图片，不选无法回到原页面的搜索缩略图。
   - 其次：没有合格图片时，从**已下载的原片**里选取清晰、对焦准确、无源文字的关键帧作为封面帧候选，记录视频文件、时间码与选取理由。不得使用播放器截图、短视频封面缩略图或最终成片反抽帧；模糊、失焦或带字的帧直接淘汰，不做修补。
2. 对每个候选记录原页面 URL（图片）或视频页面与时间码（关键帧）、直接地址（可取得时）、作者/机构、发布时间或获取时间、使用依据、原始尺寸与 SHA-256。搜索结果页只用于发现，不能替代原页面；用户提供图片时记录 `user_provided`。
3. 保存原始图片或原片到本地，不预先放大；检查主体相关、构图美观、焦点准确、曝光与颜色正常，并确认没有字幕、标题、日期、账号贴纸、水印、马赛克、明显压缩块或生成痕迹。为每张候选制作无标题 3:4 底图和 270×360 无标题缩略图，按 3.0 四项硬门评分；带硬伤或任一单项未达门槛的候选直接换图/换帧，不做修补。
4. 将有效画面按 `cover` 等比例铺满锁定 JSON `cover.background_video` 区域，根据主体移动焦点，不得拉伸。构图后仍有文字或关键主体被标题遮挡时换候选；封面禁止任何局部模糊、马赛克、生成式填充和遮字。
5. 先执行本节有效像素与等比检查，再铺设纯黑画布、放置画面、叠加透明四角框和标题。禁止使用旧版不透明暗层覆盖画面。
6. 按锁定参数排版当前新闻的 `cover_headline` 和 `cover_subline`。`cover-text-layout-v2.png` 只能用于比对，不得直接叠加示例文字。
7. 在工作区导出无损封面母版，作为最终视频的第 0 帧；同一母版的 3:4 画面区按 `config.json` 的 `output.cover_name` 交付。母版、无标题底图、两种缩略图与原始候选都保留在工作区。缩略图和编码后反抽帧只作验收，不可冒充上传封面。

禁止在封面出现：

- 新闻主播、演播室口播者、AI 播报人员；
- 图片或视频帧自带的任何可辨识标题、字幕、日期、账号贴纸或水印式说明；
- “资料画面”“素材：抖音@xxx”等素材说明；
- 第三方概念渲染、专利图或未确认真机；
- 与正文不同的产品、人物或事件；
- 纯黑或近似纯黑的整块背景、未显示可识别真实画面的空封面。

企业高管、当事人或事件主体本人可以出现，但必须是新闻主体，而不是负责播报新闻的人。AI 生成、来源不明、与正文仅有宽泛联想的图库图均不合格。

### 3.0 四项封面候选硬门

评分参数、候选数量、单项门槛、总分门槛和同分优先级只读 `config.json.cover.editorial_selection`。这些分数是基于实际图像的人工编辑判断，不得由图片尺寸、OCR、锐度统计、图像搜索排名或模型自报分数自动代替。

每张候选都必须同时查看原始画面、按最终焦点裁切的无标题 3:4 底图，以及 270×360 无标题缩略图，并分别记录以下四项：

- `technical_clarity`：主体关键轮廓、材质、动作和环境细节清楚，无失焦、拖影、蜡化、明显压缩块或过度放大；标题清楚不能补偿底图模糊。视频帧来源尤其要看运动模糊与压缩块。
- `subject_legibility`：不看标题也能在缩略图中立即辨认一个具体主体、关键动作、地点或受影响场景；远景主体过小、信息拥挤、大片空区或只能看出“某种泛场景”均不通过。
- `topic_relevance`：画面是同一事件/主体/产品/地点，或事实包明确列出的直接影响对象与动作场景；只在行业、职业、家庭等大类上相关，必须靠标题解释才能建立联系的通用图库图不通过。资料画面不能冒充现场。
- `visual_impact`：画面有一个明确强视觉中心，并至少具备关键瞬间、动作张力、尺度对比、空间纵深、鲜明但自然的光色反差或真实情绪中的一项；普通证件照、无动作会议远景、均匀平淡画面和主体被框线/标题淹没不通过。冲击力不能来自无关人脸、猎奇伤害、夸张暗化、过饱和、虚假拼贴或误导性裁切。

执行顺序：

1. 先排除来源、版权边界、字幕水印、主播、生成图、拉伸和明显低清等硬失败。
2. 把全部候选（图片与视频帧一视同仁）用同一版式裁成无标题 3:4 预览，并生成无标题 270×360 接触表；不允许不同候选用不同大小预览制造优势。
3. 对四项逐项写分数和一句可核查依据。任一项低于 config 单项门槛时立即淘汰，不得用其他高分补偿；总分还必须达到 config 总分门槛。
4. 合格候选超过一张时按 config 的同分优先级选择。只有选中候选才进入标题排版；无候选通过时调整为“具体主体 + 关键动作/地点/结果/影响对象”的检索词重新搜索，仍失败则 `BLOCKED_VISUAL`。
5. 排版后再看有标题 270×360 缩略图；如果标题遮住强视觉中心、主体变得不可辨或冲击力明显下降，优先移动底图焦点，仍不合格则换候选，不移动锁定文字模板。

`cover-quality.json` 至少保存候选数组、来源类型（图片/视频帧及时间码）、三类预览路径/哈希、四项分数、逐项依据、总分、硬失败原因、是否入选和复核人/时间。只有实际查看证据后才能填写分数；不得把所有候选机械填成门槛值。

### 3.1 原帧清晰度与有效像素

- 首轮并行保存 `config.json.cover.editorial_selection.candidate_count_range` 指定数量的来源清楚候选，先比较主题辨识度、构图和有效像素，再选一张进入封面排版；同一候选最多两轮定向裁切，仍不合格就换图/换帧，避免反复渲染。
- 排除失焦、拖影、压缩块、严重降噪蜡化和已被二次拼贴的画面。水面、树叶等高纹理画面也要能辨认具体主体与场景，不以纹理复杂自动判清晰。
- 记录原生像素与颜色模式；EXIF 方向先归一并记录，不得预先放大后伪称原生尺寸。裁切框基于归一后的原图坐标，必须保留完整未裁图片供追溯。
- 计算基于**裁切后的有效像素**，不是文件名或源视频的标称 1080p。设裁切为 `w×h`，目标区域为锁定 JSON 的 `cover.background_video`，最小铺满比例为 `s=max(目标宽/w,目标高/h)`。实际缩放层尺寸可能更大，必须记录最终实际值，并按实际横纵比例检查。
- 专用阈值从 `config.json.cover.quality` 读取：优先不放大；超过首选值但未超过硬上限时须作原帧与底图的 100% 对比，记录为何保留；超过硬上限直接换帧/换高清源，不能借用正文更宽松的阈值。阈值是本项目内部标准，不是平台公开审核规则。竖屏原片（1080×1920 及以上）的帧通常天然满足；横屏原片的帧需要足够高的源分辨率。
- 必须运行 [check_cover_geometry.py](../scripts/check_cover_geometry.py)（渲染器在准备封面时自动执行），输入原始画面、实际裁切框和**裁切后有效层**的真实缩放宽高，把报告保存在工作区。拉伸、裁切越界、未铺满或过度放大均阻止渲染；脚本不能证明来源、审美或相关性，必须与素材清单和工程参数对照。
- `GEOMETRY_OK_REVIEW_REQUIRED` 只表示几何门通过。必须在 100% 下对比原始画面、未加标题底图与最终 PNG；标题锐利不能证明底图清晰，像素尺寸也不能单独放行。

调用形式（占位参数必须换成实际值）：

```text
python scripts/check_cover_geometry.py <原始图片或封面帧PNG> --crop <左,上,宽,高> --scaled-size <实际层宽,实际层高> --cover <封面母版.png> --report <工作区验收目录/cover-geometry.json>
```

### 3.2 母版、上传图与比例

- 视频首帧和默认封面母版继续使用配置中的 9:16 画布；真实底图使用锁定的中央 3:4 区域。两者不是同一个尺寸，不能把整张 9:16 图直接压扁成 3:4，也不能把横图的宽高分别强制设成竖图尺寸。
- 背景只用单一比例缩放后裁切/移动焦点，横纵比例误差不得超过配置容差。标题和四角框不跟背景一起拉伸；不使用 `fit: fill`、非等比 `resize` 或 `scale=目标宽:目标高` 硬塞不同宽高比的原图。
- 独立封面用无损 PNG、不透明 RGB 或全部不透明的 RGBA、正确 sRGB 色彩导出。只在最后需要时重采样一次，不反复转 JPEG，不使用锐化/AI 放大作为低清源通过的依据。
- 不凭上传页缩略图形状猜测平台比例。默认交付不变；只有用户明确要求，或本次实际上传界面明确给出其他比例时，才从无损母版按该比例**裁切**导出上传候选。
- 上传时选独立全分辨率 PNG，不选 270px 缩略图、截图、聊天预览或从已压缩 MP4 反抽的首帧。必须核对实际选中文件的尺寸与 SHA-256，而非仅看扩展名。

## 4. 封面固定排版

- 主标题：经批准的粗体字体（config `layout.bold_font`，Windows 为微软雅黑粗体，macOS 为冬青黑体 W6）、青色、黑色描边；副标题：同一字体、白色、黑色描边。颜色、参考中心、描边、字号上下限与最大文字宽度只从配置及锁定 JSON 读取。
- 字号从锁定上限起步；文字宽度放不进锁定最大宽度时，按真实字形测量逐步减小到下限为止（样片封面就是这样处理的）。低于下限仍放不下必须压缩文案；两行各占一行，禁止换行、横向压缩和非等比缩放。
- 两行标题的视觉中心与参考资产一致。主体面部、产品核心部件或关键动作不得被标题遮住；构图冲突时换帧或移动背景焦点，不移动文字模板。
- 青色只能用于主标题；副标题保持白色。不要因为品牌色改成其他颜色，除非用户当次明确要求。

## 5. 缩略图验收门

全尺寸封面通过不代表信息流缩略图通过。渲染全片前必须同时检查：

1. 无标题中央 3:4 底图缩放到 270×360，先检查内容本身。
2. 完整 9:16 封面缩放到 270×480。
3. 有标题中央 3:4 区域缩放到 270×360，模拟双列信息流卡片。

无标题 270×360 预览必须先通过四项硬门，尤其是在没有文案提示时仍能看清具体内容、确认与新闻事实的直接关系，并形成明确视觉中心；否则不得进入下面的成品文字检查。

在 270×360 预览中必须满足：

- 不放大图片也能立即读出两行文字；
- 主标题仍是第一视觉层级，宽度约占安全区域 55%–95%（长主标题允许贴近上限）；
- 副标题清楚但不抢主标题；
- 两行均完整，没有触边、截字；字号不低于配置下限；
- 主体仍能被识别，文字没有压住主体关键部位；
- 四角框完整可见；
- 真实场景或主体清楚可辨，不得只剩标题、四角框和深色底板；封面 3:4 画面区内不允许出现占比超过 15% 的连续纯黑/近纯黑均匀空区。

任一项失败即 `BLOCKED_VISUAL`，先改文案或换底图，不进入全片渲染。

### 5.1 收到“封面模糊或拉伸”告警后的恢复

1. 保存告警截图、实际选中的文件名/哈希/原生尺寸、上传裁切设置及检查时间。告警本身不能区分失焦、过度放大、拉伸或选错缩略图，不能仅凭截图断言原因。
2. 先查选中的是否为独立无损原尺寸图片，再查目标比例和裁切设置；随后比对原始画面、无标题底图与上传文件的 100% 细节，并重跑几何门。原图已糊则换源；原图清楚、合成变糊则修正过度裁切、重采样或错误缩放；本地清楚但平台仍告警，检查实际上传图与界面裁切，不把模糊的平台小缩略图反过来作底图。
3. 不把点击“美化”、重复上传同一文件、修改后缀或强锐化当作问题解决。同一底图最多两轮定向修订，仍告警则换更清楚的候选；来源是视频帧时优先改为单独检索的高清图片；无合格替代时 `BLOCKED_VISUAL`，汇报具体证据，不无限重跑。
4. 平台检查独立记录 `not_checked / warning / no_warning_observed`。用户未授权上传时不擅自上传，本地可以完成交付，但必须写明“平台上传未验证”；不得填“平台已通过”。如果本次已知告警仍未解决，不得标 `FINAL_READY`。

## 6. 正文与平台的相对位置

平台叠层会盖住顶部标题栏、右侧操作栏和底部标题/评论入口。按对标成片的做法，正文允许被这些界面部分压到，但文字要自己站稳：

- 标题块每一行都能独立成句，关键事实不放在可能被顶部标题栏盖住的首行；标题块不因为避让而缩小。
- 字幕块不超过锁定宽度，居中排布，避免长行伸进右侧操作栏；字幕块底边高于底部标题/评论入口。
- 右侧和底部保留区可以继续显示实拍画面、模糊背景与来源小字，但不得新增标题、字幕、关键数字或免责小字。
- 实拍带可以横跨右侧操作栏的纵向区间——那只是画面，不是文字。
- 所有坐标与色值以 [锁定版式 JSON](../assets/references/locked-layout/layout-lock-v3.json)（`config.json` `layout` 段引用）为唯一来源，本文不复述数值。禁止恢复浮动大信息卡，或把实拍带压成狭小窗口。

## 7. 平台叠层预览门

最终 MP4 交付前，从最终编码文件重新抽取：第 1 帧、每个字幕块到达后的稳定帧、每个切点后 1 帧和末帧。把这些帧按 [平台叠层参考](../assets/references/v3-reference/platform-overlay-reference.webp) 的遮挡关系检查，或在目标平台的草稿预览中检查。

以下任一项直接失败：

- 字幕块、标题块第 2 行以后、结果行或免责小字与账号头像、右侧按钮、评论入口重合到无法完整阅读；
- 为避让平台 UI 把文字缩到手机端难以阅读；
- 字幕块越出锁定宽度或字幕区，板块边界偏离锁定 JSON 超过容差（config.json `layout.tolerance_px`）；
- 平台预览后才发现文字被挡，却仍将文件标记为最终版。

平台界面可能变化；如果用户提供了新的平台截图，以新截图测量覆盖范围并调整保留区，不能缩小默认安全区而不做实际预览。
