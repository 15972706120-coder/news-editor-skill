# 资讯快讯节点式 SOP

> 所有节点先读取 [当前制作配置](current-production-profile-v3.md)。历史规则只保留在 CHANGELOG。

本 SOP 用于完整制作或涉及多个制作环节的任务。没有指定主题的完整制作从 N0 开始；用户已经提供主题时可从 N1 开始。定向修改只执行相关节点，但必须保留需求建档、受影响节点和 N11 的验收闭环。

## 节点执行纪律

- 每个节点必须先生成本节点交付物，再根据实际文件、页面或检测结果填写验收结论；不得只在回复里声称“已检查”。当前节点没有通过，不进入下一节点。
- 工作区保存 `workflow-status.md`，逐节点记录 `未开始 / 进行中 / 通过 / 阻塞`、证据文件、失败原因和恢复入口。失败后回到最近一个可靠节点继续，不能从头盲目重跑，也不能跳过失败项用占位内容补齐。
- 自动化脚本的参数值不等于视觉或听觉通过。涉及封面、裁切、模糊、字幕到达帧、切点和平台遮挡时必须保存并实际查看预览；涉及时长、帧数和响度时必须保存机器检测结果。
- 完整制作默认使用本文件给出的固定参数。用户只要求局部修改时，先列“修改项、保持项、受影响节点”，只重跑受影响节点和 N11。
- 生产台账、平台发布台账、事实与表达一致性检查按 [编辑与数据反馈闭环](editorial-feedback-loop.md) 执行。`FINAL_READY`、用户验收与平台发布是不同状态，不用文件修改时间或本地输出代替真实发布时间。
- 用户要求 N 条时按合格交付上限执行，默认仅 1–2 条在制；每条开工前重新读取台账并刷新事实与素材条件。候选不足、过时或被排除时少交付并说明。
- 故障区分事实/来源、素材/封面、声音/渲染、工具/访问及版本问题，分别记录证据、尝试、最后有效进展和恢复入口。只在确认故障后中止受影响任务；保留可用工件及哈希，输入变化才重跑受影响节点。

## N-1｜GitHub 最新版本启动门

**目标**：保证本次运行使用启动时 GitHub `main` 的精确 commit，而不是本机旧副本、缓存分支或仅版本号相同的文件。

**动作**：在 N0/N1 和所有任务动作之前，根 Agent 为本次用户请求生成新 `run_id`，执行 `scripts/ensure_latest_skill.ps1`。需要子智能体时同时指定 `-ManifestOut`，只在最终 `LATEST_READY` 后创建父运行清单；角色、阶段屏障、任务包和交接包按 [子智能体编排规范](subagent-orchestration.md) 执行。`LATEST_READY` 可进入后续节点；`UPDATED_READY_RELOAD` 必须先重新完整读取新版 `SKILL.md`、`config.json` 与本次需要的 references，并确认活动 SHA 等于脚本返回的远端 SHA。任何非零退出码立即记为 `BLOCKED_SKILL_VERSION`；不得在断网、脏工作树、错误远程、分支不符、历史分叉或新版校验失败时使用本机旧版继续。版本门通过后本次运行固定该 commit，运行中不切换规范。

**验收门**：根版本门 JSON 属于本次新 `run_id`；最终状态为 `LATEST_READY`；`active_sha == remote_sha`；若发生更新，已重新读取并用同一 `run_id` 重跑新版 gate。使用子智能体时，父清单路径、SHA-256 与活动 commit 已锁定，每个子智能体均以同一 `run_id` 取得 `CHILD_CONTEXT_READY`。复核时又发生更新则阻塞。

**节点交付**：不使用子智能体时在上下文保留完整版本门 JSON，并在 N1 记录其字段；使用子智能体时由版本门直接原子写入 `run-manifest.json`，根 Agent 保存脚本返回的清单 SHA-256，子任务只接收清单路径/哈希与任务包，不记录凭据。

## N0｜今日选题搜寻与候选交付

**目标**：在用户未指定主题时，按账号实测的题材优先级和 S/A/B 分级，找到当天值得制作、能够核验、具备素材条件的新闻候选。

**动作**：

- 以北京时间和最近 24 小时为默认窗口，至少组合一个趋势平台与一个综合新闻平台进行发现，并按 [选题发现与筛选规范](topic-discovery.md) 的题材种子词主动检索。
- 不使用新华社/新华网、央视新闻/央视网、人民日报/人民网、中国新闻社等国家级媒体的新闻内容、转载稿或账号内容；在聚合平台逐条核对实际署名和原始来源。
- 从 10–20 条原始线索中合并重复事件，先过红线（无信源、改写度不足、时间错位等），再定 S/A/B，同级按题材优先级排序。
- 使用政府部门、法院、警方、企业/机构公告、当事方回应、地方媒体、行业媒体或商业媒体核验事件主体、时间、关键数字与最新进展。
- 为每个候选记录合格来源页面的完整原始信息标题，并以该标题在抖音预查直接相关视频的可得性，同时探查封面来源（独立图片优先，其次原片清晰关键帧）与原声线索。
- 抖音预查只验证“是否存在可用素材线索”，不在用户选定主题前批量下载。
- 对照生产与平台发布台账，评估快讯适配性（字数、标题块、素材时长、封面、成片形态）与风险。

**验收门**：候选均有可点击链接、完整原始信息标题、分级理由和台账核对结论；来源署名不属于国家级媒体；素材与封面存在可行线索；热搜排名没有被当作事实证据。没有足够合格候选时说明不足，不能为满足数量造题。

**选择门**：先把候选交付用户。用户选定主题后再进入 N1；只有用户明确授权“由你选择”时，才可代选。

**节点交付**：候选主题表、Top 3 推荐和来源说明；完整项目保存为 `topic-scout.md`。

## N1｜需求与输入建档

**目标**：把用户意图转成无歧义的制作约束。

**必须确认或推断**：主题、成片形态（`brief_video` 或 `brief_text`）、音频模式、画布与帧率、标题块与字幕块文案、封面来源类型、素材角色、参考样式、输出位置。

**动作**：

- 检查每个本地文件是否存在、可读、可解码；把参考图、样片、文案和用户指令分开记录。
- 对未指定但风险较低的参数使用明确默认值；会改变内容含义或成本的缺口才询问用户。
- 在 `project-brief.md` 中分别列出“用户明确要求、固定默认值、允许推断、不得改变的保持项”。成片形态：有覆盖全片的真实素材用视频形态；没有素材但信息本身成立用纯图文形态。音频模式：默认 BGM；有当事方原话用原声加 BGM；用户要求才配音。
- 记录内容目的、目标受众、相对既有内容的新增事实，以及本轮选题代选和发布授权范围。滚动制作不自动授权上传或平台发布。
- 正式进入制作时按反馈闭环登记在制占位和关联事件，防止并发及已制作未发布作品再次入选。
- 建立双目录：工作目录为 `<项目根>/.news-editor-work/YYYY-MM-DD/N.中文新闻短名/`，输出目录为 `<输出根>/YYYY-MM-DD/N.中文新闻短名/`（输出根见 `config.json` 的 `output.root`）。未达到 `FINAL_READY` 前不创建或写入输出主题目录。

**验收门**：输入可访问，关键规格不冲突，授权范围明确。

**节点交付**：需求摘要、输入清单、默认假设和待确认项；完整项目保存为 `project-brief.md` 与 `inputs-manifest.json`。

## N2｜选题与事实包

**目标**：形成可追溯的新闻事实基础。

**动作**：

- 若主题来自 N0，对入选候选执行更深入的交叉核验；若用户直接提供主题，从本节点开始建立事实包并执行同样的国家级媒体排除检查。
- 对日期、主体、事件、回应和关键数字进行交叉核验；核心事实至少使用两个相互独立的可靠来源，存在政府/机构原始发布或当事方回应时必须纳入。
- 锁定一条非国家级来源的完整原始信息标题作为 `canonical_source_title`。
- 事实包按字段记录 `who / when / where / what / response / result / key_numbers / uncertainty / latest_verified_at`；每条关键数字或回应紧邻支持它的链接。
- 将事件发生、素材拍摄、原始发布和最新实质进展四类时间分别留证；不得把转载时间当发生时间，或把旧画面当当前现场。周报复盘的“时间错位”就出在这里。
- 对照历史事实，同事件无新增事实时停止；必要纠错、不同事故、新回应或新统计须给新增/修正事实与来源。
- 事实锁定后立即做 N4 的素材与封面前置可行性探针；探针未通过不启动渲染。直入 N1 的指定主题也须执行。
- 不把搜索摘要、评论或二次解读直接写成事实。

**验收门**：核心事实至少有两个相互独立的来源支撑；`canonical_source_title` 与来源页面一致；没有国家级媒体内容或链接；四类时间未混淆；时效性及事实增量判断留证；素材与封面前置探针通过；争议点使用中性表达。

**节点交付**：选题理由、事实摘要、争议点、来源清单和素材边界；完整项目保存为 `fact-pack.md`。

## N3｜新闻文案包

**目标**：把事实变成适合快讯的信息层级。

**文案结构**：

- 标题块：2–3 行，每行一个独立成句的信息点，顺序为“背景或反常点 → 核心事实 → 反转或细节”，末行为黄色斜体；纯图文形态为 1 行斜体标题。
- 结果行（可选）：判决、回应或落地时间等结论，1 行。
- 字幕块：3–4 块，每块 1–4 行、一个信息点，总字数在 config 区间内；纯图文形态为最多 3 段逐行正文并标黄关键词。
- 封面短文案：主标题与副标题，字宽不超过 config 硬上限。
- 发布标题：可选，不填时取标题块各行以空格连接。
- 来源行：真实来源，只渲染在右下角小字安全框内，不进入标题块与结果行。

**动作**：先写事实版，再做短视频压缩。第一块直接给最重要的事实；事件类后续块依次给回应、结果、影响，政策类给条件、时间、怎么办；已知回应不故意延迟。每块先按阅读下限估算停留，渲染后按手机尺寸实际复核，不能先定秒数再硬塞文字。保留限定词、否定词、数字和主体；文字短化不能改变含义，资料画面不能被写成现场。按反馈闭环保存表达映射并执行一致性检查，机器通过后仍须实际阅读全文。

**验收门**：标题块与字幕块和事实包一致，无标题党式偷换；每块字宽与总字数在 config 限内；阅读下限能容纳全部信息；封面短文案不超字宽硬上限。

**节点交付**：`copy-deck.md`，至少列出标题块各行与样式、结果行、每个字幕块的行与阅读停留、纯图文高亮词（如适用）、封面主副标题和来源行。

## N4｜素材获取与媒体体检

**目标**：取得可用、合规、技术上可靠的素材与封面来源。

**动作**：

- 先复核 N2 的素材与封面可行性探针及当前可访问状态；已失败则保留工件、记录阻塞并换候选，不重复支付成本后才检查基础可做性。
- 把 N2 的 `canonical_source_title` 原样作为抖音首条搜索词；只允许删除标点、话题符号或无信息量前后缀。首轮不足时只能在完整标题后附加地点、主体或“现场”等限定词，不得脱离原题另搜泛化素材。
- 首轮同事件结果若全部是主播、口播人脸或单一近景，先保留至少一条可追溯的事实素材，再建立 `scene_keywords` 做第二类场景检索；场景词必须由事实包中的受影响人群、地点、动作和办理流程推导。
- 每个主题下载 1–5 条相关视频（上限见 config），合计可用时长覆盖成片；抖音是优先路径但不是唯一来源，其他公开页面中的视频也必须可追溯、符合授权边界并完整解码。国家级媒体及其平台账号内容不进入候选。
- 下载前打开每个候选的规范化 `/video/<id>` 页面，逐条记录“为什么与原始标题是同一事件”。仅下载用户授权或公开允许的素材；不绕过访问控制；保存原始文件，不直接覆盖。
- 用媒体探针记录时长、尺寸、帧率、编码、音轨、旋转信息和文件大小；下载后完整解码验证并计算哈希；生成接触表，识别稳定镜头、内置转场、黑边、水印、主播镜头、字幕区和其他画面内文字。
- 为每个候选片段登记角色：`direct_evidence`（事件现场/当事方/官方画面）、`contextual_broll`（资料画面）、`first_hand_quote`（当事方或目击者原话）。资料画面不得冒充现场；原话片段记录清晰的语音区间，供原声模式使用。
- 逐段记录 `subject_identity`、`footage_type`、`supports_claim`、`misleading_risk`、`footage_role`、`face_dominant`、`scene_category`、源入/出点、目标裁切与原文字区域。主播、AI 主播、对镜口播和单人脸部近景不能作为核心画面；人脸主导时长超过正文 20% 时补搜场景化素材。
- 无法找到至少一段合格视频且信息不适合纯图文形态时，停止该主题并返回 N0 更换选题；禁止用自生成画面、无关库存画面或主播补足。
- 封面来源：先按 config 数量单独检索高清图片；没有合格图片时从已下载原片选取清晰、无源文字的关键帧。两类候选都记录来源（图片的原页面与 URL，关键帧的视频文件与时间码）、使用依据、尺寸和哈希；制作无标题 3:4 裁切图和 270×360 缩略图，按四项人工评分写明证据。不得使用播放器截图、平台缩略图或成片反抽帧。
- 可检索少量新闻相关高清图片或事实信息截图作为补充；信息截图需裁去浏览器工具栏、广告、评论和无关推荐，并把可见文字映射到 fact-pack 的 claim。

**验收门**：至少一段可解码视频且全部来源可追溯（或已确认走纯图文形态）；首条抖音查询与规范化标题一致；角色、人脸与场景符合规范；封面候选数量符合配置且四项人工评分全部达标；正文静态候选的来源、事实用途和授权边界完整。

**节点交付**：原始视频、封面候选及其无标题裁切图/缩略图/候选接触表、`cover-quality.json`、可选正文图片/截图、`source-manifest.md`、`media-report.json`、视频接触表和候选时间码。

## N5｜干净素材与画面区域

**目标**：得到不带旧标题干扰、适合实拍带的画面。

**动作**：

- 逐个候选片段识别原始字幕、标题条、日期条、说明文字和素材内部黑边；优先改用本身无字的时间段，或通过裁剪、等比放大和焦点位移把文字移出实拍带。
- 对位于画面底部、裁剪后会伤害主体的字幕，可以做跟随字幕区域的局部强模糊，使其完全不可辨认，边缘自然且不遮挡主体；不得用暗化、黑色遮罩、马赛克或新文字覆盖。
- **例外**：已核对的当事方原话片段（`first_hand_quote`）允许保留源字幕与原声，因为原话与字幕本身是新闻内容；须逐句核对字幕文字与事实包一致。
- 顶部/中部标题、日期条和大面积说明文字仍应移除；处理不达标时换时间段、拼接其他片段或更换素材。
- 保持目标分辨率且不拉伸。每个计划使用的时间段按最终实拍带渲染首、中、末帧目标裁切预览，先看结果再决定是否可用。
- 封面只从 N4 四项人工评分全部达标的候选中选择；只做裁切、等比缩放、焦点调整和轻度全局色彩调整；文字、水印、模糊、马赛克或修补均失败，直接换候选。
- 正文图片按最终实拍带导出起止预览；信息截图的目标文字全程清晰可读，不应用字幕模糊。

**验收门**：除已核对的原话片段外，使用帧中不存在可辨识的原始文字；允许的底部字幕模糊完全不可读、范围克制；实拍带被真实画面完整覆盖，无黑边、黑带或空白；输出尺寸准确。

**节点交付**：`clean-clip-*.mp4`（如需）、处理前后对比帧，以及裁剪、缩放、位移、模糊和拼接参数说明。

## N6｜剪辑计划与时间轴

**目标**：用稳定且能表达事件的画面覆盖字幕块节奏。

**动作**：

- 先选内容相关性，再看稳定性、清晰度和动作连续性。按“建立场景 → 主体/动作 → 回应/结果”选互补片段，单段通常 1.6–5 秒（见 config），镜头之间硬切。
- 可以从同一条素材选取多个时间段，也可以跨源拼接；不重复同一时段、不变速、不冻结凑时长。
- 按音频模式排字幕块：默认与原声模式按阅读下限（`plan_reading_frames` 给初稿）；配音模式先逐块合成并实测时长（`plan_voice_frames` 给初稿）。块边界落在完整语义处。
- `edit-plan.md` 每段必须包含：源文件/视频 ID、源入点、源出点、目标入点、目标出点、目标帧数、角色、`supports_claim`、裁切/缩放/位移、模糊框与时间段。每个字幕块写明信息任务、阅读依据、最低停留与到达帧。没有完整字段的片段不得进入时间轴。
- 图片/信息截图单段设置首尾关键帧：缓慢推近或拉远，锚点位移克制，线性运动；关键帧运动按 config 的超采样倍数渲染。评论截图浮层最多一个，写出起止帧与位置。
- 选定音频模式与 BGM 文件并在计划中记录。

**验收门**：真实视频覆盖正文主要时长；静态素材段数和占比不超过 config；每个字幕块对应画面支持其文字；人脸、主播、场景、切点、原始文字与字幕处理全部通过；AI 自生成主体画面为零。

**节点交付**：`edit-plan.md` 与 `timeline.json`（通过 `production_contract.py` 检查）。

## N7｜视觉系统、正文与封面

**目标**：把对标样式的排版规则落成可复现的画面。

**动作**：

- 用户没有另行指定样式时，读取并复现 [视觉与声音模板](visual-audio-template.md) 与 [锁定版式](locked-layout-validation.md)：字体、字号上下限、倾斜、描边、标签、字幕滑入、实拍带与背景全部由锁定 JSON 决定。封面和发布版式读取 [封面与平台安全布局](cover-platform-layout-v3.md)。
- 用户提供新的参考样式时，提取颜色、字号、字重、边距、圆角、描边、阴影和装饰元素；仅覆盖用户明确改变的固定模板属性，并记录像素差。
- 封面先执行四项人工门与几何门，再看带标题封面、中央 3:4 裁切后的 270×360 双列缩略图和平台叠层预览。
- 先渲染预览：封面、缩略图、每个字幕块的定格图与滑入序列、标题区包装层、每个剪辑段的首中末帧；全部看过再渲染全片。平均亮度或颜色统计不能替代视觉检查。

**验收门**：文字不溢出、无错字；标题块末行为黄色斜体，结果行为独立红字行；资料画面有免责小字；实拍带满幅；封面四项人工评分全部达到配置阈值，带标题缩略图可辨认主体并读出两行文字；字幕块宽度与位置符合锁定；平台叠层中关键文字可读。

**节点交付**：`封面.png`（母版的 3:4 区域）、预览图和可复现的渲染报告。

## N8｜声音

**目标**：形成与对标成片一致的清晰、克制的声音。

**动作**：

- 默认 `bgm_only`：从内置曲库按题材情绪选一首 BGM，在 `edit-plan.md` 记录；避开歌词和抢占中频的人声元素。不需要 TTS 凭据。
- `original_bgm`：仅当事方原话片段保留原声；试听确认原声清晰、能听懂，并与源字幕一致；嘈杂的原声改用默认模式。
- `tts_bgm`（仅用户要求）：启动 TTS 前确认事实锁定及素材/封面探针通过；按 [MiniMax TTS 集成](minimax-tts.md) 逐字幕块合成、试听并实测时长。
- 混音后检查淡入淡出与响度；按当前音频模式的目标（综合响度区间与真峰值上限见 config）在最终 MP4 上实测；有突出音频（原声或配音）时逐区间测量其与 BGM 的差值。

**验收门**：最终 MP4 的综合响度与真峰值在当前模式的目标内；原声/配音区间 BGM 低于人声 config 规定的分贝数（容差见 config）；无爆音、削波、突然断尾；手机外放可听清。

**节点交付**：`mix.wav`、人声与 BGM stem、`mix.json` 及口播时间码（配音模式）。

## N9｜合成与草稿

**目标**：生成可评审的完整视频。

**动作**：按时间轴合成画面、字幕、封面、BGM（与原声或配音）；在内部工作区使用版本号并保留上一版；开启适合网络播放的 MP4 元数据布局。草稿、预览、脚本、截图和测试素材只放 `.news-editor-work`，不得写入输出区。草稿完成后从草稿文件重新抽取第 0 帧、第 1 帧、每个字幕块到达帧、每个切点前后帧和末帧，连同 270×360 封面缩略图一起查看，再交用户评审。

**验收门**：文件能完整播放；实际解码帧数等于计划；画面和声音起止一致；无缺帧或超时。

**节点交付**：`draft-v01.mp4`、关键帧预览和本版变更摘要。

## N10｜反馈与定向修订

**目标**：准确落实用户标注，不引入旁支变化。

**动作**：把自然语言或截图标注换算成对象、区域、数值和保持项；在 `revision-log.md` 写明修改项、保持项、受影响节点和回退版本；修改前复述理解；修改后先比较受影响帧及相邻帧，再重新执行所有受影响的机器/视觉/听觉门和 N11。

**验收门**：标注区域、文字属性和时间点与反馈一致；未要求的元素保持不变。

**节点交付**：新版本草稿、受影响前后对比和 `revision-log.md`。

## N11｜最终验收与交付

**目标**：交付可发布、可复核的最终文件。

**动作**：

- 完整制作由独立只读 QA 复核事实、四类时间和标题/字幕/画面映射，再核对成片与验收证据；QA 不修片、不改生产文件。未做试听或视觉检查明确记录未检查。
- 交付前刷新事实与内容有效性，按反馈闭环核对台账状态和一致性报告。支付宝上传仅在用户已验收且明确授权时按 [平台发布管线](alipay-publish-pipeline.md) 进行。
- 对最终编码 MP4 运行机器检查：容器/视频流/音频流时长、实际解码帧数、尺寸、帧率、编码、采样率、声道、综合响度和真峰值。实际帧数必须来自完整解码，不得由容器时长推算。
- 视觉检查第 0 帧、第 1 帧、每个字幕块到位帧与滑入过程、每个切点、末帧；手机尺寸静音看一遍，确认每个字幕块读得完，带声音看一遍。
- 单独验收上传封面：无标题 270×360 缩略图、候选接触表、带标题 270×360 双列缩略图、四项人工评分与字号记录；用平台叠层参考确认关键文字未被挡到不可读。
- 对照 `source-manifest.md` 确认每个镜头可追溯到已登记的视频、图片或截图及其角色；资料画面带免责小字，原话片段的字幕与原声已核对。
- 听觉检查：BGM 无接缝与削波；有原声或配音时人声完整、BGM 避让到位。
- 状态达到 `FINAL_READY` 后，使用 `scripts/publish_news_output.ps1`（输出根目录缺省从 config.json 读取）把一个最终 MP4 和一个封面 PNG 输出为 `<输出根>/YYYY-MM-DD/N.中文新闻短名/<cover_title_full>.mp4` 与 `封面.png`；重新输出时把旧版归档到工作区历史版本目录。运行 `scripts/check_output_layout.ps1` 确认目录结构。
- 对最终 MP4 与封面计算 SHA-256，写入工作区验收记录；最终回复只链接稳定输出文件。按反馈闭环登记生产与验收结果；用户验收和平台发布各自发生后再记录。

**验收门**：按 [delivery-gates.md](delivery-gates.md) 完成 G0–G8；可辨识原始干扰文字残留为零（已核对的原话片段除外）；自生成主体画面、大块黑边、主播画面、主体身份不一致均为零；封面四项人工评分全部达到配置阈值；主播/AI 主播/对镜口播为零；字幕块满足阅读下限；静态素材未超 config 限额；当前音频模式的响度与真峰值通过；链接可用；状态为 `FINAL_READY`；发布目录检查通过。

**节点交付**：发布区默认仅交付最终 MP4 与 `封面.png`；用户明确需要时可增加 `发布文案.txt`、`来源说明.md` 或 `配音.wav`。`qa-report.json`、工程说明、素材与工程源文件保留在内部工作区。
