# 当前制作配置 V3（最高优先级）

本文件记录 2.0 的配置决策及其依据。具体数值只存在于 `config.json` 与锁定 JSON，本文不复述；被取代的分页版式、14 秒固定时长、强制配音和“封面只能用独立图片”等规则只保留在 CHANGELOG 中供回看旧成片。

## 1. 为什么重构

运营反馈与周报显示：账号流量靠少数头部内容的命中率；人工编辑制作的 9–13 秒“BGM＋字幕”资讯条是主要流量来源，而旧流程（固定 14 秒、MiniMax 逐页配音、深海蓝分页正文板）产出的内容条均明显偏低，并反复出现“配音与字幕不匹配”“选题热度不足”“时间错位”三类问题。本次以账号四条高播放成片为对标，逐帧实测后重做整条流程：

- 四条样片均为 720×1280 的平台转码件，时长 10–13 秒，第 0 帧即封面。
- 语音识别确认其中三条没有配音（纯 BGM），第四条保留的是素材里当事方的采访原声。
- 正文为“2–3 行混排标题块＋真实素材带＋黄字黑边字幕”，字幕带运动模糊从右侧滑入并随阅读节奏逐块替换；没有分页、页码和正文板。
- 封面与既有模板完全一致（青色大字＋白色副标题＋四角框＋手写线），因此封面体系原样保留。
- 四条样片的原件与截帧自 2.0.4 起不再随仓库分发（含第三方画面）。下文凡是写“样片实测”的数值都已固化到 `config.json` 与锁定 JSON，`assets/references/v3-reference/` 的参考图改用开放授权的真实视频帧渲染，封面从素材帧截取。

## 2. 成片形态与时长

- 有素材用视频形态，没有素材但信息成立（政策更新、时间表、清单）用纯图文形态。
- 时长不再固定，由 3–4 个字幕块的阅读节奏相加得出，通常 9–13 秒；超过上限先删信息，仍需延长要取得用户授权且不超过硬上限。旧版的紧凑档/标准档与“不要凑时长”原则合并为这一条。

## 3. 声音

- **默认不配音。** 字幕承载全部信息，音频只有 BGM。这既是对标样片的实际做法，也消除了配音与字幕不一致的风险，并让默认链路不依赖任何外部 API。
- 素材原话本身是新闻时保留原声，BGM 在原声区间自动压低；原声按响度上限封顶，避免整体增益把它推得过响。
- MiniMax 配音降为可选模式，仅用户明确要求时使用；音色与参数沿用 2026-09-04 的试听定版，凭据只在首次实际生成前检查。

## 4. 响度

四条样片的综合响度实测在 -11 到 -13 LUFS 之间，真峰值 -1.5 到 -3 dBTP，明显比旧设定的 -16 LUFS 更响。字幕＋BGM 类成片因此对齐样片实测目标；配音模式沿用原来的响度区间。各模式的区间与上限见 config `mix.loudness_targets`。

## 5. 版式

- 坐标、字号、颜色、倾斜、描边、字幕滑入帧数全部写入 `layout-lock-v3.json`，人读镜像见 [锁定版式与分区验收](locked-layout-validation.md)。
- 标题块自固定底边向上堆叠，实拍带顶边只随结果行与免责小字变化；实拍带之外由渲染器用素材模糊副本自动填充。
- 标题、字幕、结果行的字号从锁定上限起步、按真实字形宽度自适应到下限。旧版固定字号遇到 7–8 个字的封面标题必然溢出，而样片本身就是自适应字号。
- 来源小字保留在右下角（延续 1.12 的决定：媒体名不进标题区）。四条样片没有这行字，但它对版权与溯源有必要，所以保留为小号灰字，不抢眼。

## 6. 字幕节奏与字数

- 每块停留下限按样片实测拟合：基础秒数＋每字宽秒数×字宽，且不小于最小块时长。样片里每块约 2.4–4.5 秒。
- 字幕 3–4 块、每块不超过 4 行、总字数区间见 config；单行字宽上限按样片最长行放宽。行宽与实拍带要避开平台右侧操作栏和底部入口，因此标题块每行都要能独立成句。
- 纯图文版逐行出现并累加，末块完整显示后保留收尾停留。

## 7. 封面

- 封面样式不变。**来源放宽**：优先单独检索的高清图片；没有合格图片时可用已下载原片的清晰关键帧，须记录时间码、通过同一套几何门与四项人工门，并明确查看过清晰度与无源文字。起因是“必须单独找图”在多数社会新闻上直接导致无法开工，而三条样片的封面本来就是素材帧。
- 取消“固定 144/112 字号、禁止缩字”，改为上限字号＋按宽度自适应到下限；两行字宽硬上限不变，超过必须改写文案。
- 平台曾出现“封面模糊或拉伸”告警，因此几何门（放大倍率上限）与人工清晰度复核都保留，不因来源放宽而降低。

## 8. 选题

- 默认方向从“科技产业与消费科技”改为账号实测的题材优先级：人物故事/情感纠纷、社会民生、手机数码风险、消费维权与食品安全、清单型实用信息为主，科技品牌大事件与国际见闻为辅。
- 新增 S/A/B 分级与红线，与团队热点清单和冲刺方案的口径一致（S 级当日优先、A 级择优、B 级不做；无信源、改写度不足、时间错位不发）。详见 [选题发现与筛选规范](topic-discovery.md)。

## 9. 素材口径

- 片段分为事件现场、资料画面、当事方原话三种角色。资料画面允许使用，但片头必须打“视频资料与新闻事件无关”，与样片做法一致；它不得冒充现场或当事人。
- 当事方原话片段可以保留源字幕与原声——这是样片留存表现好的做法，旧版“一律清除源字幕”会破坏这类内容。
- 其片段的源字幕、标题条仍须移除或局部强模糊；主播、AI 主播、对镜口播仍为零。
- 评论截图允许作讨论氛围浮层（最多一个、限时），但不得作为事实来源；文字材料截图按信息截图规则核验。

## 10. 保留不变的规则

来源排除（国家级媒体不作发现来源与交付链接）、双来源核验、四类时间、台账与去重、输出区与工作区分离、文件命名、编辑记录门、平台发布管线、版本门与子智能体编排全部沿用。

## 11. QA 证据边界

`FINAL_READY` 同时要求：机器硬门（尺寸、帧率、帧数、音频规格、当前模式响度、真峰值、命名一致性）；机器警告（OCR 候选、锐度、码率、黑区、冻结帧）；必须人工完成的复核（封面四项门、实拍带源文字、字幕到达帧与阅读节奏、平台遮挡、事实一致性、最终音轨试听）。每项记录证据文件、帧号或试听区间与检查时间。

## 12. 已知限制

- 新渲染链路在 macOS（替代字体）和 GitHub 的 Windows 主机（微软雅黑粗体）上跑通了全链路与冒烟测试；生产机上的首次运行仍应先执行 `smoke_test_brief_pipeline.py`，确认字体观感与其 FFmpeg 版本行为一致。
- **macOS 制作（2.1.0）**：环境检查、输出脚本、字体和输出目录的配置支持 macOS。Mac 上没有微软雅黑，用的是系统自带的冬青黑体 W6（2026-11-25 经用户看过同版式对比后批准）：骨架和疏密接近微软雅黑粗体，笔画略轻，同一账号混用两套字体出片时要留意观感一致。已通过单元测试、冒烟测试和版式参考图重建，**尚未在 macOS 上完成一条真实成片**，抖音检索下载与平台发布待首次实跑。
- 响度目标取自平台转码件，平台是否二次归一化未知；上线后以实际播放听感为准微调。
- **bgm-03 暂不可用于默认模式**：它的前 14 秒峰值与响度之比过大，混音器只做线性增益，`bgm_only` 模式下达不到响度目标（实测 2026-11-25：响度 -16.1 LUFS 时真峰值才回到 -1.7 dBTP）。默认模式下用 bgm-01 或 bgm-02；要继续使用 bgm-03 需要重新制作母带或给混音器加限幅，后者尚未实现。
- 配音模式只用合成音频验证了管线，没有做真实 MiniMax 回归；首次启用时按 [MiniMax TTS 集成](minimax-tts.md) 逐块试听。
- 阅读下限是机器底线，不等于观众一定读得懂；每条成片仍须手机尺寸静音复核。
- **升级兼容存根**：旧版版本门脚本在快进之后仍按旧清单校验，所以 `current-production-profile-v2.md` 只是一个不含规则的转向文件，V2 锁定文件里的 status 也仍写着 active。两者都不参与现行制作，不要据它们执行；等全部生产机升到 2.0.0 之后可在后续版本清理。今后改名版本门清单里的文件，也要为上一版脚本照样留一个存根。
