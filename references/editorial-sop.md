# 新闻短视频节点式 SOP

> **当前覆盖规则**：所有节点先读取 [当前制作配置 V2](current-production-profile-v2.md)。N7/N8/N11 中冲突的 V1 坐标、Edge TTS、封面模糊和旧命名示例不再执行。

本 SOP 用于完整制作或涉及多个制作环节的任务。没有指定主题的完整制作从 N0 开始；用户已经提供主题时可从 N1 开始。定向修改只执行相关节点，但必须保留需求建档、受影响节点和 N11 的验收闭环。

## 节点执行纪律

- 每个节点必须先生成本节点交付物，再根据实际文件、页面或检测结果填写验收结论；不得只在回复里声称“已检查”。当前节点没有通过，不进入下一节点。
- 工作区保存 `workflow-status.md`，逐节点记录 `未开始 / 进行中 / 通过 / 阻塞`、证据文件、失败原因和恢复入口。失败后回到最近一个可靠节点继续，不能从头盲目重跑，也不能跳过失败项用占位内容补齐。
- 自动化脚本的参数值不等于视觉或听觉通过。涉及封面、裁切、模糊、切点和平台遮挡时必须保存并实际查看预览；涉及时长、帧数和响度时必须保存机器检测结果。
- 完整制作默认使用本文件给出的固定参数。用户只要求局部修改时，先列“修改项、保持项、受影响节点”，只重跑受影响节点和 N11。

## N-1｜GitHub 最新版本启动门

**目标**：保证本次运行使用启动时 GitHub `main` 的精确 commit，而不是本机旧副本、缓存分支或仅版本号相同的文件。

**动作**：在 N0/N1 和所有任务动作之前，为本次运行生成新 `run_id`，执行 `scripts/ensure_latest_skill.ps1`。`LATEST_READY` 可进入后续节点；`UPDATED_READY_RELOAD` 必须先重新完整读取新版 `SKILL.md`、`config.json` 与本次需要的 references，并确认活动 SHA 等于脚本返回的远端 SHA。任何非零退出码立即记为 `BLOCKED_SKILL_VERSION`；不得在断网、脏工作树、错误远程、分支不符、历史分叉或新版校验失败时使用本机旧版继续。版本门通过后本次运行固定该 commit，运行中不切换规范。

**验收门**：版本门 JSON 属于本次新 `run_id`；状态允许继续；`active_sha == remote_sha`；若发生更新，已完成重新读取；没有执行强制覆盖或使用上次运行记录。

**节点交付**：先在上下文保留完整版本门 JSON；N1 建立工作区后写入 `run-manifest.json`，记录 `run_id`、状态、核验时间、版本和 SHA，不记录凭据。

## N0｜今日选题搜寻与候选交付

**目标**：在用户未指定主题时，主动找到当天值得制作、能够核验、具备素材条件的新闻候选。

**动作**：

- 以北京时间和最近 24 小时为默认窗口，至少组合一个趋势平台与一个综合新闻平台进行发现，例如微博热搜与腾讯新闻、今日头条。
- 不使用新华社/新华网、央视新闻/央视网、人民日报/人民网、中国新闻社等国家级媒体的新闻内容、转载稿或账号内容；在聚合平台逐条核对实际署名和原始来源。
- 从 10–20 条原始线索中合并重复事件，排除国家级媒体来源、来源不清、事实无法核验、版权或安全风险过高的选题。
- 使用政府部门、法院、警方、企业/机构公告、当事方回应、地方媒体、行业媒体或商业媒体核验事件主体、时间、关键数字与最新进展。
- 为每个候选记录合格来源页面的完整原始信息标题，并以该标题在抖音预查直接相关视频的可得性。
- 抖音预查只验证“是否存在可用素材线索”，不在用户选定主题前批量下载；至少打开一条结果页确认是同一事件，不能只凭搜索卡片文字判断。
- 依次评估时效性、公共价值、短视频表达力、素材可得性和风险，筛选 5–8 个候选并给出 Top 3 推荐。
- 每个候选必须提供一句话摘要、原始信息标题、事件时间、合格的非国家级来源或原始发布、事实核验链接、抖音素材线索和风险提示。

**验收门**：至少有 5 个去重候选；每个候选有可点击链接和完整原始信息标题；来源署名不属于国家级媒体；推荐理由可解释；热搜排名没有被当作事实证据。

**选择门**：先把候选交付用户。用户选定主题后再进入 N1；只有用户明确授权“由你选择”时，才可代选评分最高且风险可控的候选继续。

**节点交付**：候选主题表、Top 3 推荐和来源说明；完整项目保存为 `topic-scout.md`。详细规则见 [topic-discovery.md](topic-discovery.md)。

## N1｜需求与输入建档

**目标**：把用户意图转成无歧义的制作约束。

**必须确认或推断**：主题、目标平台、画布、时长、帧率、主副标题、分页文案、配音要求、BGM、封面、参考样式、输出位置、是否保留原声。

**动作**：

- 检查每个本地文件是否存在、可读、可解码。
- 将参考图、样片、文案和用户指令分开记录。
- 对未指定但风险较低的参数使用明确默认值；会改变内容含义或成本的缺口才询问用户。
- 在 `project-brief.md` 中分别列出“用户明确要求、固定默认值、允许推断、不得改变的保持项”。默认完整制作写明 1080×1920、30fps、14.000 秒、420 帧、封面第 0 帧、双页、MiniMax 新闻女声配音、BGM 和是否保留原声。
- 建立双目录：工作目录为 `<项目根>/.news-editor-work/YYYY-MM-DD/N.中文新闻短名/`，输出目录为 `<输出根>/YYYY-MM-DD/N.中文新闻短名/`（输出根见 `config.json` 的 `output.root`）。序号按当日完成生产并输出的顺序确定；未达到 `FINAL_READY` 前不创建或写入输出主题目录。

**验收门**：输入可访问，关键规格不冲突，授权范围明确。

**节点交付**：需求摘要、输入清单、默认假设和待确认项；完整项目可保存为 `project-brief.md` 与 `inputs-manifest.json`。

## N2｜选题与事实包

**目标**：形成可追溯的新闻事实基础。

**动作**：

- 若主题来自 N0，对入选候选执行更深入的交叉核验；若用户直接提供主题，从本节点开始建立事实包并执行同样的国家级媒体排除检查。
- 对日期、主体、事件、回应和关键数字进行交叉核验；核心事实至少使用两个相互独立的可靠来源，存在政府/机构原始发布或当事方回应时必须纳入。
- 锁定一条非国家级来源的完整原始信息标题作为 `canonical_source_title`；记录来源标题、链接、发布日期、事件日期和可用素材线索。
- 事实包按字段记录 `who / when / where / what / response / result / key_numbers / uncertainty / latest_verified_at`；每条关键数字或回应紧邻支持它的链接，不能只在文末堆来源。
- 不把搜索摘要、评论或二次解读直接写成事实。

**验收门**：核心事实至少有两个相互独立的来源支撑；`canonical_source_title` 与来源页面一致；没有国家级媒体内容或链接；事件日期与报道日期未混淆；争议点使用中性表达。

**节点交付**：选题理由、事实摘要、争议点、来源清单和素材边界；完整项目保存为 `fact-pack.md`。

## N3｜新闻文案包

**目标**：把事实变成适合短视频的信息层级。

**文案结构**：

- 主标题：问题或核心事件，短、具体、有信息量。
- 副标题：来源、回应或结论，不重复主标题。
- 内容简介：包含时间、主体、事件和结果。
- 分页正文：每页只承担一个信息任务。
- 分页视觉文案：每页明确拆成 `white_lines`（1–2 行事实说明）与 `red_emphasis`（1 行结论、关键数字或动作）；红色重点不是渲染器自动猜测，而是文案阶段就锁定。
- 配音稿：与页面同步；可逐字版与口播版并存。
- 来源行：展示真实来源，不虚构媒体名称。

**动作**：先写事实版，再做短视频压缩；保留限定词、否定词、数字和主体。第一页只承担“谁、何时、发生什么”，第二页承担“回应、规则、影响、结果或进展”；两个页面不得重复同一句背景。先写逐页口播稿并分别生成试音，按实测时长修订文案，再锁定页面帧数，不能先平均分帧后强行塞配音。

默认分页执行 [visual-audio-template.md](visual-audio-template.md)：标准成片 14.000 秒、420 帧、封面占第 0 帧、正文默认 2 页。每页通常 20–42 个全角字宽、最多 3 行；先生成分段配音并测时，再按语义和真实语音长度分配共 419 个正文帧，不再固定 4 秒/页或按字符数机械加页。固定 14 秒无法自然容纳时先精简并保持双页，只有用户允许延长或关键信息不可删时才增加页面。

**验收门**：完整报道标题与正文一致，无标题党式偷换；另有符合 V2 字数上限的短封面主副标题；配音能在目标时长内自然说完；所有页面语义完整；没有为了塞入时长而缩字或明显加速。

**节点交付**：`copy-deck.md`，至少列出主标题、副标题、每页 `white_lines`、`red_emphasis`、完整配音稿和来源行。任一页没有红色重点字段不得进入视觉节点。

## N4｜素材获取与媒体体检

**目标**：取得可用、合规、技术上可靠的素材。

**动作**：

- 把 N2 的 `canonical_source_title` 原样作为抖音首条搜索词；只允许删除标点、话题符号或无信息量前后缀，不得改成宽泛的主体词或同类事件词。搜索记录必须保存实际查询词。
- 同时保存规范化后的标题和查询词，并明确记录两者是否一致；不一致时不得继续选材。
- 若首轮结果不足，可在完整原始标题后附加地点、主体或“现场”等限定词，但查询中仍必须完整保留原始标题；不得脱离原题另搜泛化素材。
- 首轮同事件结果若全部是主播、口播人脸或单一近景，先保留至少一条可追溯的事实/事件素材，再建立 `scene_keywords` 做第二类场景检索。场景词必须由事实包中的受影响人群、地点、动作和办理流程推导，例如“灵活就业 办公工作”“家长 带孩子 生活”“社保 生育保险 办事大厅”；禁止只搜“职场”“家庭”等无约束大词。
- 场景检索得到的片段标记为 `contextual_broll`，只用于说明政策影响对象、生活场景或办理流程，不得冒充事件现场或当事人。完整项目仍优先控制在 1–3 条下载视频内，并在 `source-manifest.md` 分开记录精确标题查询与场景查询。
- 每个主题下载 1–3 条与原始标题所指事件直接相关的视频。国家级媒体及其平台账号内容不进入候选素材；优先事件现场、主体行动、地点、设备、流程或结果镜头。
- 下载前打开每个候选的规范化 `/video/<id>` 页面，逐条记录“为什么与原始标题是同一事件”；只凭关键词、账号名称或封面相似不得下载为正式候选。
- 仅下载用户授权、公开允许或用户明确要求处理的素材；不绕过访问控制。
- 保存原始文件，不直接覆盖。
- 用媒体探针记录时长、尺寸、帧率、编码、音轨、旋转信息和文件大小。
- 下载后对每个文件执行完整解码验证并计算哈希；只有文件可完整解码、时长与页面一致且非空壳文件，才进入接触表筛选。
- 生成接触表或按间隔抽帧，识别稳定镜头、内置转场、黑边、水印、主播镜头、字幕区和其他画面内文字。
- 建立素材清单，逐条记录原始信息标题、实际查询词、抖音页面链接、账号、平台标题、下载文件、媒体规格、版权/使用边界和候选时间码。
- 候选时间码不能只写画面描述，还要记录源入/出点、可用秒数、页面职责、支持的正文、目标裁切/缩放/位移、原文字区域、动态文字风险、局部模糊框和封面适用性。
- 为每个候选片段填写 `subject_identity`、`footage_type`、`supports_claim`、`misleading_risk` 与原始文字区域。其他产品或事件、`unrelated` 片段直接淘汰；第三方渲染、专利图、通用测试和历史画面不得冒充真机、现场或默认封面。
- 另外填写 `footage_role=direct_evidence/contextual_broll`、`face_dominant` 和 `scene_category`。主播、AI 主播、对镜口播和单人脸部近景不能作为核心画面；若首批候选的人脸主导时长超过正文画面的 20%，必须补搜并换入场景化素材后才能进入 N5。
- 无法找到至少一条合格视频时停止该主题制作并返回 N0 更换选题；禁止用自生成画面、无关库存画面或主播封面补足。

**验收门**：已下载 1–3 条可解码视频；首条查询与规范化标题一致；场景扩展词来自事实包并有记录；每条都能追溯；所有实际使用候选的角色、主体身份与正文一致；主播/AI 主播画面为零，单人脸部近景计划占比不超过正文画面的 20%；至少覆盖 2 个不同场景类别；稳定实拍片段总时长满足剪辑计划；至少存在一个无原文字、非主播、非第三方渲染且主体清楚的封面候选；来源与授权边界可说明。

**节点交付**：1–3 条原始素材、`source-manifest.md`、`media-report.json`、每条素材的 `contact-sheet.png` 和候选片段时间码。

## N5｜干净素材与画面区域

**目标**：得到不带旧标题干扰、适合重新排版的画面。

**动作**：

- 逐个候选片段识别原始字幕、标题条、日期条、说明文字和素材内部黑边；优先改用本身无字的时间段，或通过裁剪、等比例放大和焦点位移把文字移出有效内容区。
- 对位于画面底部、裁剪后会伤害主体或破坏满幅构图的字幕，可以做跟随字幕区域的局部强模糊。模糊必须让文字完全不可辨认，边缘自然且不遮挡主体；不得用暗化、黑色遮罩、马赛克或新文字覆盖，也不得把字幕模糊扩展成整幅模糊背景补边。
- 顶部/中部标题、日期条和大面积说明文字仍应通过换时间段、裁剪或重新构图移除。若底部字幕模糊后仍可辨认、模糊区过大或遮挡主体，先换用同一素材的其他时间段，或从已下载素材中选择多个短段拼接；仍不达标时再更换素材或返回 N4 重新检索。
- 保持目标分辨率且不拉伸。裁剪后用 `cover` 逻辑等比例放大并移动视觉焦点，铺满模板的中间内容区域；禁止 `contain` 后产生上下或左右大块黑边，也不使用黑底或模糊复制背景补边。
- 对封面底图识别“有效影像区”，裁掉素材内部已有黑边和文字后再铺满指定区域。
- 每个计划使用的时间段都要按最终实拍区域渲染目标裁切预览，并保存首帧、中帧、末帧。先看目标裁切后的结果，再决定是否可用；不能仅凭原始接触表通过。
- 封面遵循“换帧/重构图优先、精确局部模糊最后”的顺序。只允许模糊实际残留的原始文字框；禁止把顶部、右侧或底部大块有效画面整体模糊。模糊后主体在 270×360 缩略图中必须仍然明确。

**验收门**：所有使用帧中不存在可辨识的原始文字；允许的底部字幕模糊区域完全不可读、范围克制且不遮挡主体；中间内容区被真实下载画面完整覆盖，无大块黑边、黑带或空白；主体未被关键裁切；输出尺寸与像素范围准确。

**节点交付**：`clean-master.mp4` 或多段 `clean-clip-*.mp4`、处理前后对比帧，以及裁剪、缩放、位移、底部字幕模糊和拼接参数说明。

## N6｜剪辑计划与时间轴

**目标**：用稳定且能表达事件的画面覆盖目标时长。

**动作**：

- 先选内容相关性，再看稳定性、清晰度和动作连续性。
- 时间轴中的新闻主体画面必须全部来自 N4 下载的 1–3 条视频；禁止插入 AI 生成图片/视频、自制地图或信息图、抽象动画、纯色占位、无关库存素材或合成主播。
- 可以从同一条素材选取多个时间段，也可以从已下载的 1–3 条素材中跨源选择并拼接；优先用多个内容相关的短段解决单段字幕、构图或变化不足的问题。
- 记录每段源时间码、目标时长、速度、页面归属和切点。
- `edit-plan.md` 每段必须包含：源文件/视频 ID、源入点、源出点、目标入点、目标出点、目标帧数、页面归属、`supports_claim`、裁切/缩放/位移、模糊框与时间段、速度和切换方式。没有完整字段的片段不得进入时间轴。
- 单段通常使用 1.5–4 秒；稳定且信息密度高的关键现场可以更长。优先按“建立场景 → 主体/动作 → 回应/结果”选择互补片段，避免长时间静止、无意义闪切、原素材内置转场或为凑时长重复同一镜头。
- 14 秒双页成片至少使用 2 个场景类别；建议为 3 类，例如“政策/机构信息、职场或办理过程、家庭或照护场景”。单个单人脸部近景不超过 1.5 秒，全部 `face_dominant=true` 片段合计不超过正文画面的 20%；主播、AI 主播和对镜口播镜头不得进入最终时间轴。
- 默认 30fps、14.000 秒共 420 帧；封面只占第 0 帧，正文页合计 419 帧。每页帧数由分段配音实测时长、0.15 秒入场和至少 0.25 秒尾音决定，写成明确列表，例如 `210,209`，并按 [visual-audio-template.md](visual-audio-template.md) 核对总和。
- 源片段不足时可轻度慢放；避免明显卡顿或重复。
- 用户要求直接切换时，抽查切点前后帧，避开源素材自带叠化。

**验收门**：选中片段的实际干净时长能够覆盖全部正文帧；总时长精确；每页都有来自下载素材且支持该页文字的对应画面；至少 2 个场景类别，人脸主导占比不超过 20%，主播/AI 主播/对镜口播为零；切点没有重影、黑帧、可辨识的原始文字或无意义特写；底部字幕模糊始终不可读且不突兀；没有任何自生成新闻主体画面。

**节点交付**：`edit-plan.md`，包含源入点、源出点、目标区间、速度与转场规则。

## N7｜视觉系统、正文与封面

**目标**：把参考样式转成可复现的排版规则。

**动作**：

- 用户没有另行指定样式时，读取并复现 [visual-audio-template.md](visual-audio-template.md) 的固定微软雅黑字体、字号、行高、颜色、位置、圆角、描边和装饰元素；封面和发布版式还必须读取 [cover-platform-layout-v2.md](cover-platform-layout-v2.md)，直接使用拆分的四角框资产并检查缩略图与平台叠层参考。
- 用户提供新的参考样式时，提取颜色、字号、字重、边距、圆角、描边、阴影和装饰元素；仅覆盖用户明确改变的固定模板属性。
- 保持用户明确要求不变的属性；修改位置时记录像素差。
- 默认竖屏画布为 1080×1920。3:4 封面图片区通常为 1080×1440；具体位置服从用户标注。
- 封面底图必须选自 N4 下载视频中的非主播、非演播室镜头，并与事件直接相关；禁止把新闻播报人员、主持人、口播者或 AI 主播作为封面。
- 封面底图必须铺满指定区域，文字和角标压在底图上；素材内部黑边不能冒充设计留白。封面原始文字必须先完全裁除。
- 封面先通过换帧、裁切和焦点位移保留主体信息；只有确实残留的原始文字框允许精确局部模糊。模糊面积明显吞掉主体、地点或关键动作时必须换帧，不能以“文字不可读”作为唯一通过依据。
- 封面另写短文案：主标题 4–7 个全角字宽、硬上限 8，副标题 5–10 个全角字宽、硬上限 12；固定使用 144px/112px，禁止通过缩字容纳长文案。
- 正文使用确认成片实测的深海蓝三段式（标题板、副标题条、黄线、实拍板、正文板）：底板固定为深海蓝渐变，禁止纯黑；全部坐标只从 `config.json` 的 `layout` 段引用的锁定 JSON 读取，文档不复述数值。红字允许与左侧蓝色 Logo 轻微重叠，但至少 75% 字面面积和完整语义可读。
- 封面使用透明 `cover-frame-lines-v3.png`，不能把旧版不透明暗层覆盖到真实底图。3:4 封面区必须能清楚看见下载素材中的主体/场景；只剩标题、四角框和黑色/近黑色背景直接失败。
- 首先渲染封面、中央 3:4 裁切后的 270×360 双列缩略图、第一页、第二页、切点和平台叠层预览，再渲染全片。
- 对每个实际使用片段的开头、中间、结尾以及每个切点前后逐帧查看；平均亮度或颜色像素统计不能替代视觉检查。

**验收门**：文字不溢出、无错字；每页存在独立红色重点行且与白色说明形成层级；下载画面满幅；封面不是新闻播报人员、不存在原始文字、纯黑空底或不透明暗层遮画面；透明四角框、固定字号与短标题符合规范；270×360 缩略图可直接辨认主体并读出两行文字；平台叠层中白字不被遮挡，红字受 Logo 遮挡不超过 25%；已对草稿运行 `extract_layout_proof.py` 并实际查看每个分板，边界与 `layout-lock-v2.json` 相差不超过 2px；封面与正片风格一致。

**节点交付**：`cover.png`、各页面预览图、视觉参数摘要和可复现工程源文件。

## N8｜新闻女声、BGM 与混音

**目标**：形成清晰、可信、不过度表演的新闻声音。

**动作**：

- 固定使用 [visual-audio-template.md](visual-audio-template.md) 定义的普通话新闻女声；同一项目所有页面和后续版本保持同一 TTS 提供方、模型与 voice ID，语气克制、重音准确。
- 分页分别合成，按页面切点放置；只做必要的轻度时间压缩。
- 每页单独输出试音并记录原文、音频秒数、起止帧、入场余量和尾音余量；页面切点必须落在完整句或自然停顿。合成总配音前先确认各页试音均能在分配帧内自然结束。
- 每页音频必须在分配的页帧内完整结束，并保留开头与尾音余量。无法自然容纳时，优先精简口播措辞、调整双页语义；只有总时长允许时才增加页面。若改写，保留事实并展示口播稿。
- BGM 默认从技能内置的 `assets/audio/bgm-01.mp3`、`bgm-02.mp3`、`bgm-03.mp3` 中选择一首；用户指定其他原创、已授权或用户提供素材时以用户选择为准。避开歌词和抢占中频的人声元素。
- 先测量选中 BGM 片段和对应人声区间的响度，再通过归一化、分段音量或侧链让播报期间 BGM 比人声低 12dB，验收容差 ±1dB；不得对三首原始文件统一机械减 12dB。
- 混音后做淡入淡出、限幅和响度检查；默认成片目标为约 -16 LUFS、真峰值不高于 -3 dBTP。
- 保留独立人声 stem 与 BGM stem；逐页测量播报重叠区间，最终还要从编码后的 MP4 复测整体响度和真峰值，不能只检查中间 WAV。

**验收门**：每句在对应页面内说完；播报重叠区间的 BGM 比人声低 12dB、误差不超过 ±1dB；无爆音、削波、突然断尾；手机外放可听清。

**节点交付**：`voice.wav`、`bgm.wav`、混音版音轨或成片，以及口播时间码。

## N9｜合成与草稿

**目标**：生成可评审的完整视频。

**动作**：按时间轴合成画面、文字、封面、配音和 BGM；在内部工作区使用版本号并保留上一版；开启适合网络播放的 MP4 元数据布局。草稿、预览、脚本、截图和测试素材只放 `.news-editor-work`，不得写入输出区。草稿完成后必须从草稿文件重新抽取第 0 帧、第 1 帧、每页中点、每个切点前后帧和末帧，连同 270×360 封面缩略图一起查看，再交用户评审。

**验收门**：文件能完整播放；画面和声音起止一致；无缺帧或超时。

**节点交付**：`draft-v01.mp4`、关键帧预览和本版变更摘要。

## N10｜反馈与定向修订

**目标**：准确落实用户标注，不引入旁支变化。

**动作**：把自然语言或截图标注换算成对象、区域、数值和保持项；在 `revision-log.md` 写明修改项、保持项、受影响节点和回退版本；修改前复述理解；修改后先比较受影响帧及相邻帧，再重新执行所有受影响的机器/视觉/听觉门和 N11，不能因为是“小改”跳过最终验收。

**验收门**：标注区域、文字属性和时间点与反馈一致；未要求的元素保持不变。

**节点交付**：新版本草稿、受影响前后对比和 `revision-log.md`。

## N11｜最终验收与交付

**目标**：交付可发布、可复核的最终文件。

**动作**：

- 对最终编码 MP4 机器检查容器时长、视频流时长、音频流时长、实际解码帧数、尺寸、帧率、视频编码、音频编码、采样率、声道、综合响度和真峰值。实际帧数必须来自完整解码或 `ffprobe -count_frames`，不得由容器时长推算。
- 视觉检查第 0 帧、第 1 帧、每个切点、正文稳定帧和末帧。
- 单独导出第 0 帧的 270×360 双列缩略图，检查封面短标题、144px/112px 字号、四角框、主体和源文字；再用平台叠层参考检查每页代表帧，确认关键文字未进入右侧或底部保留区。
- 对每个实际使用片段至少检查开头、中间、结尾三帧，确认没有动态出现的可辨识原始字幕或标题；若使用底部字幕模糊，检查其全程不可读、边缘稳定且不遮挡主体。检查内容区四边，确认没有大块黑边、黑带、空白或作为补边使用的模糊背景。
- 对照 `source-manifest.md` 确认每个主体镜头均可追溯到下载素材；确认封面不是新闻播报人员。
- 听觉检查人声完整度、BGM 平衡、静音和削波。
- 每页分别测量人声与 BGM stem 的播报重叠区间，确认差值为 12±1dB；中间 WAV 结果不能代替最终 MP4 的响度与真峰值。
- 用最终文件重新抽帧，不以渲染前预览代替。
- 状态达到 `FINAL_READY` 后，使用 `scripts/publish_news_output.ps1`（输出根目录缺省从 config.json 读取）把一个最终 MP4 和一个封面 PNG 输出为 `<输出根>/YYYY-MM-DD/N.中文新闻短名/<cover_title_canonical>.mp4` 与 `封面.png`；重新输出时把旧版归档到工作区历史版本目录。
- 运行 `scripts/check_output_layout.ps1`，确认日期、连续序号、中文命名、文件数量和禁止项全部通过。
- 对最终 MP4 与封面计算 SHA-256，并把哈希、最终文件名、输出路径、实际帧数、最终响度和 `FINAL_READY` 状态写入工作区验收记录；最终回复只能链接该稳定输出文件，不能链接草稿或历史版本。

**验收门**：按 [delivery-gates.md](delivery-gates.md) 完成 G0–G8；所有检查通过；可辨识原始文字残留、自生成主体画面、大块黑边、主播封面、第三方渲染封面和主体身份不一致均为零；封面使用深海蓝底板、真实下载画面与 V3 透明四角框，270×360 缩略图和平台叠层预览通过；正文至少覆盖 2 类场景，主播/AI 主播/对镜口播为零，人脸主导时长不超过 20%，每页具有白色说明与红色重点；允许的底部字幕局部模糊已通过全时段检查；链接可用；状态为 `FINAL_READY`；发布目录检查通过，且没有把工程、脚本、截图、测试素材、临时、草稿、历史版本或损坏文件当作交付。

**节点交付**：发布区默认仅交付最终 MP4 与 `封面.png`；用户明确需要时可增加 `发布文案.txt`、`来源说明.md` 或 `配音.wav`。`qa-report.json`、工程说明、素材与工程源文件保留在内部工作区，不污染发布目录。
