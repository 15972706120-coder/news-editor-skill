> 先执行 [当前制作配置 V2](current-production-profile-v2.md)。本文件为活动规范；历史规则只保留在 CHANGELOG，封面零模糊/零马赛克，不适用正文字幕清理例外。

## 2. 封面文案不是新闻长标题

封面承担缩略图点击识别，不复述完整报道标题。先从事实标题中提炼两层信息：

- `cover_headline`：主体或最强事件钩子，理想 4–7 个全角字宽，硬上限 8。
- `cover_subline`：结果、场景或第二信息点，理想 5–10 个全角字宽，硬上限 12。
- 两行合计硬上限 18 个全角字宽；同一事实不得在两行重复。
- 汉字和全角符号计 1；ASCII 字母或数字计 0.55；半角标点计 0.5。计数只是预筛，最终必须以实际字体测量宽度为准。
- 主标题不写完整日期、来源名称和“发布/宣布/回应称”等弱信息前缀，除非日期本身就是新闻钩子。
- 禁止通过减小字号容纳长文案。超过宽度时必须重新压缩文案。

通过示例：

```text
苹果新CEO
首场发布会

机器人闪电
百米8秒94再破纪录
```

失败示例：

```text
小鹏机器人融资超9亿美元
腾讯、阿里参与战略投资

小米玄戒三芯齐发
手机到智驾全栈AI算力
```

失败原因不是事实错误，而是字数过多迫使字号缩小，在双列信息流中失去第一视觉层级。

## 3. 封面合成顺序

画布固定为 1080×1920，合成顺序不可颠倒：

1. 以新闻主体、地点、设备、动作或受影响场景为关键词，单独检索高清图片；禁止从任何视频抽帧、播放器截图、短视频封面缩略图或最终成片反抽。优先原始发布方/机构媒体库、当事方公开图片和可追溯摄影图片，不选无法回到原页面的搜索缩略图。
2. 对每个候选记录原页面 URL、直接图片 URL（可取得时）、作者/机构、发布时间或获取时间、使用依据、原始文件尺寸与 SHA-256。搜索结果页只用于发现，不能替代原页面；用户提供图片时记录 `user_provided`。
3. 保存下载到本地的原始图片，不预先放大；检查主体相关、构图美观、焦点准确、曝光与颜色正常，并确认没有字幕、标题、日期、账号贴纸、水印、马赛克、明显压缩块或生成痕迹。为每张候选制作无标题 3:4 底图和 270×360 无标题缩略图，按 3.0 四项硬门评分；带硬伤或任一单项未达门槛的候选直接换图，不做修补。
4. 将有效图片按 `cover` 等比例铺满锁定 JSON `cover.background_video` 区域，根据主体移动焦点，不得拉伸。构图后仍有文字或关键主体被标题遮挡时换图；封面禁止任何局部模糊、马赛克、生成式填充和遮字。
5. 先执行本节有效像素与等比检查，再铺设深海蓝渐变、放置独立图片、叠加透明四角框和标题。禁止使用旧版不透明暗层覆盖图片。
6. 按本文件固定参数重新排版当前新闻的 `cover_headline` 和 `cover_subline`。`cover-text-layout-v2.png` 只能用于比对，不得直接叠加示例文字。
7. 在工作区导出无损封面母版，作为最终视频的第 0 帧；默认将同一母版按 `config.json` 的 `output.cover_name` 交付。母版、无标题底图、两种缩略图与独立原始候选图片均保留在工作区。缩略图和编码后反抽帧只作验收，不可冒充上传封面。

禁止在封面出现：

- 新闻主播、演播室口播者、AI 播报人员；
- 图片自带的任何可辨识标题、字幕、日期、账号贴纸或水印式说明；
- “资料画面”“素材：抖音@xxx”等素材说明；
- 第三方概念渲染、专利图或未确认真机；
- 与正文不同的产品、人物或事件。
- 纯黑或近似纯黑的整块背景、未显示可识别真实画面的空封面。

企业高管、当事人或事件主体本人可以出现，但必须是新闻主体，而不是负责播报新闻的人。AI 生成、来源不明、与正文仅有宽泛联想的图库图均不合格。

### 3.0 四项封面候选硬门

评分参数、候选数量、单项门槛、总分门槛和同分优先级只读 `config.json.cover.editorial_selection`。这些分数是基于实际图像的人工编辑判断，不得由图片尺寸、OCR、锐度统计、图像搜索排名或模型自报分数自动代替。

每张候选都必须同时查看原始图片、按最终焦点裁切的无标题 3:4 底图，以及 270×360 无标题缩略图，并分别记录以下四项：

- `technical_clarity`：主体关键轮廓、材质、动作和环境细节清楚，无失焦、拖影、蜡化、明显压缩块或过度放大；标题清楚不能补偿底图模糊。
- `subject_legibility`：不看标题也能在缩略图中立即辨认一个具体主体、关键动作、地点或受影响场景；远景主体过小、信息拥挤、大片空区或只能看出“某种泛场景”均不通过。
- `topic_relevance`：画面是同一事件/主体/产品/地点，或事实包明确列出的直接影响对象与动作场景；只在行业、职业、家庭等大类上相关，必须靠标题解释才能建立联系的通用图库图不通过。场景 B-roll 不能冒充现场。
- `visual_impact`：画面有一个明确强视觉中心，并至少具备关键瞬间、动作张力、尺度对比、空间纵深、鲜明但自然的光色反差或真实情绪中的一项；普通证件照、无动作会议远景、均匀平淡画面和主体被框线/标题淹没不通过。冲击力不能来自无关人脸、猎奇伤害、夸张暗化、过饱和、虚假拼贴或误导性裁切。

执行顺序：

1. 先排除来源、版权边界、视频帧、字幕水印、主播、生成图、拉伸和明显低清等硬失败。
2. 把全部候选使用同一版式裁成无标题 3:4 预览，并生成无标题 270×360 接触表；不允许不同候选用不同大小预览制造优势。
3. 对四项逐项写分数和一句可核查依据。任一项低于 config 单项门槛时立即淘汰，不得用其他高分补偿；总分还必须达到 config 总分门槛。
4. 合格候选超过一张时按 config 的同分优先级选择。只有选中候选才进入标题排版；无候选通过时调整为“具体主体 + 关键动作/地点/结果/影响对象”的检索词重新搜索，仍失败则 `BLOCKED_VISUAL`。
5. 排版后再看有标题 270×360 缩略图；如果标题遮住强视觉中心、主体变得不可辨或冲击力明显下降，优先移动底图焦点，仍不合格则换候选，不移动锁定文字模板。

`cover-quality.json` 至少保存候选数组、三类预览路径/哈希、四项分数、逐项依据、总分、硬失败原因、是否入选和复核人/时间。只有实际查看证据后才能填写分数；不得把所有候选机械填成门槛值。

### 3.1 原帧清晰度与有效像素

- 首轮并行保存 `config.json.cover.editorial_selection.candidate_count_range` 指定数量的来源清楚候选图，先比较主题辨识度、构图和有效像素，再选一张进入封面排版；同一候选最多两轮定向裁切，仍不合格就换图，避免反复渲染。
- 排除失焦、拖影、压缩块、严重降噪蜡化和已被二次拼贴的图片。水面、树叶等高纹理画面也要能辨认具体主体与场景，不以纹理复杂自动判清晰。
- 记录图片原生像素与颜色模式；EXIF 方向先归一并记录，不得预先放大后伪称原生尺寸。裁切框基于归一后的原图坐标，必须保留完整未裁图片供追溯。
- 计算基于**裁切后的有效像素**，不是文件名或源视频的标称 1080p。设裁切为 `w×h`，目标区域为锁定 JSON 的 `cover.background_video`，最小铺满比例为 `s=max(目标宽/w,目标高/h)`。实际缩放层尺寸可能更大，必须记录最终实际值，并按实际横纵比例检查，不能只记录理论最小值。
- 专用阈值从 `config.json.cover.quality` 读取：优先不放大；超过首选值但未超过硬上限时须作原帧与底图的 100% 对比，记录为何保留；超过硬上限直接换帧/高清源，不能借用正文更宽松的阈值。阈值是本项目内部标准，不是平台公开审核规则。
- 必须运行 [check_cover_geometry.py](../scripts/check_cover_geometry.py)，输入原始图片、实际裁切框和**裁切后有效层**的真实缩放宽高，把报告保存在工作区。拉伸、裁切越界、未铺满或过度放大均阻止渲染；脚本不能证明来源、审美或相关性，必须与素材清单和工程参数对照。
- `GEOMETRY_OK_REVIEW_REQUIRED` 只表示几何门通过。必须在 100% 下对比原始图片、未加标题底图与最终 PNG；标题锐利不能证明底图清晰，像素尺寸也不能单独放行。

调用形式（占位参数必须换成实际值；尺寸来自配置与锁定 JSON，不手填另一套模板）：

```text
python scripts/check_cover_geometry.py <原始高清图片> --crop <左,上,宽,高> --scaled-size <实际层宽,实际层高> --cover <封面母版.png> --report <工作区验收目录/cover-geometry.json>
```

### 3.2 母版、上传图与比例

- 视频首帧和默认封面母版继续使用配置中的 9:16 画布；真实底图使用锁定的中央 3:4 区域。两者不是同一个尺寸，不能把整张 9:16 图直接压扁成 3:4，也不能把横图的宽高分别强制设成竖图尺寸。
- 背景只用单一比例缩放后裁切/移动焦点，横纵比例误差不得超过配置容差。标题和四角框不跟背景一起拉伸；不使用 `fit: fill`、非等比 `resize` 或 `scale=目标宽:目标高` 硬塞不同宽高比的原图。
- 独立封面用无损 PNG、不透明 RGB 或全部不透明的 RGBA、正确 sRGB 色彩导出。只在最后需要时重采样一次，不反复转 JPEG，不使用锐化/AI 放大作为低清源通过的依据。
- 不凭上传页缩略图形状猜测平台比例。默认交付不变；只有用户明确要求，或本次实际上传界面明确给出其他比例时，才从无损母版按该比例**裁切**导出上传候选。目标为中央 3:4 时直接取锁定区域，不缩放；其他比例须确认标题与四角框完整可用，否则停下确认适配方案，不擅自改版。
- 额外平台候选仅放工作区；在有明确要求并通过验收后，选定的一张以 `封面.png` 交付，仍不额外增加默认文件。9:16 首帧母版保留工作区，记录与上传图的派生关系及尺寸。未经确认不改变默认封面比例。
- 上传时选独立全分辨率 PNG，不选 270px 缩略图、截图、聊天预览或从已压缩 MP4 反抽的首帧。必须核对实际选中文件的尺寸与 SHA-256，而非仅看扩展名。

## 4. 封面固定排版

- 主标题：微软雅黑粗体，字号/颜色与参考中心只从配置及锁定 JSON 读取；在主标题安全宽度内居中，保留黑色描边。
- 副标题：微软雅黑粗体、白色，字号/参考中心只从同一配置读取；在副标题安全宽度内居中，保留黑色描边。两级文字实际可见边界由字体测量，不把文字原点当成可见左上角；实现见 [可执行制作链路](executable-production.md)。
- 主副标题必须各占一行，禁止换行、横向压缩、非等比缩放和自动缩字。
- 两行标题的视觉中心与参考资产一致。主体面部、产品核心部件或关键动作不得被标题遮住；构图冲突时换帧或移动背景焦点，不移动文字模板。
- 青色只能用于主标题；副标题保持白色。不要因为品牌色改成橙色、红色或其他颜色，除非用户当次明确要求。

## 5. 缩略图验收门

全尺寸封面通过不代表信息流缩略图通过。渲染全片前必须同时检查：

1. 无标题中央 3:4 底图缩放到 270×360，先检查内容本身。
2. 完整 9:16 封面缩放到 270×480。
3. 有标题中央 3:4 区域 `crop=1080:1440:0:240` 后缩放到 270×360，模拟双列信息流卡片。

无标题 270×360 预览必须先通过四项硬门，尤其是在没有文案提示时仍能看清具体内容、确认与新闻事实的直接关系，并形成明确视觉中心；否则不得进入下面的成品文字检查。

在 270×360 预览中必须满足：

- 不放大图片也能立即读出两行文字；
- 主标题仍是第一视觉层级，宽度约占安全区域 55%–88%；
- 副标题清楚但不抢主标题；
- 两行均完整，没有触边、截字或缩成小字；
- 主体仍能被识别，文字没有压住主体关键部位；
- 四角框完整可见。
- 真实场景或主体清楚可辨，不得只剩标题、四角框和深色底板；封面 3:4 画面区内不允许出现占比超过 15% 的连续纯黑/近纯黑均匀空区。

任一项失败即 `BLOCKED_VISUAL`，先改文案或换底图，不进入全片渲染。

### 5.1 收到“封面模糊或拉伸”告警后的恢复

1. 保存告警截图、实际选中的文件名/哈希/原生尺寸、上传裁切设置及检查时间。告警本身不能区分失焦、过度放大、拉伸或选错缩略图，不能仅凭截图断言原因。
2. 先查选中的是否为独立无损原尺寸图片，再查目标比例和裁切设置；随后比对原始图片、无标题底图与上传文件的 100% 细节，并重跑几何门。原图已糊则换源；原图清楚、合成变糊则修正过度裁切、重采样或错误缩放；本地清楚但平台仍告警，检查实际上传图与界面裁切，不把模糊的平台小缩略图反过来作底图。
3. 不把点击“美化”、重复上传同一文件、修改后缀或强锐化当作问题解决。同一底图最多两轮定向修订，仍告警则换更清楚的独立高清图片；无合格替代时 `BLOCKED_VISUAL`，汇报具体证据，不无限重跑。
4. 平台检查独立记录 `not_checked / warning / no_warning_observed`。用户未授权上传时不擅自上传，本地可以完成交付，但必须写明“平台上传未验证”；不得填“平台已通过”。如果本次已知告警仍未解决，不得标 `FINAL_READY`。告警消失只代表本次预览未再提示，不保证正式审核通过或推荐效果。

## 6. 正文平台安全布局

平台叠层会覆盖底部账号、发布标题、操作栏和评论入口。默认 1080×1920 采用以下保守安全区：

```text
白色正文安全区：锁定 JSON 的 white_copy_safe_bbox
红色强调允许区：锁定 JSON 的 red_emphasis_safe_bbox
右侧交互保留区：x=850–1080, y=700–1810
底部平台高风险区：x=0–1080, y=1790–1920
```

右侧和底部保留区可以继续显示无文字的实拍画面或非关键信息，但不得新增主副标题、白色正文、关键数字、页码或来源。红色强调行可以进入平台账号栏的垂直区间，并与左侧蓝色账号 Logo 轻微重叠；平台预览中至少 75% 红字面积和完整语义仍需可读。

默认正文页使用确认成片实测的锁定三段式结构，不使用浮动大信息卡；所有坐标、尺寸与色值以 [锁定版式 JSON](../assets/references/locked-layout/layout-lock-v2.json)（`config.json` `layout` 段引用）为唯一来源，本文不复述数值：

- 顶部标题区：深海蓝渐变底板（锁定 JSON `body_page.header`）。主标题为微软雅黑粗体、黄色、居中、单行（字号见同字段）；副标题条为 `subtitle_bar`，内部黑色粗体、单行。
- 黄色分隔线：`divider`；副标题与视频之间不得出现额外空隙。
- 实拍层：`body_page.footage`。真实下载素材按 `cover` 铺满，先裁出有效影像区再等比例放大和移动焦点；禁止 `contain`、黑边、空白或模糊复制背景。
- 正文区：全宽深海蓝渐变底板 `copy_board`。栏目角标 `section_label`、页码 `page_number_safe_bbox`；正文固定拆为 1–2 行白色说明与 1 行红色重点。
- 关键文字边界：白字 `white_copy_safe_bbox`、红字 `red_emphasis_safe_bbox`、来源 `source_safe_bbox`、底部黄线 `bottom_accent`；平台右侧保留区 `platform.right_reserved_*`（来源行除外）。
- 正文区可以延续到画布底部，但使用同一深海蓝渐变，不使用纯黑。除非用户当次明确指定，禁止恢复浮动大卡片、把实拍层压成狭小窗口，或以整幅模糊画面作为背景。

## 7. 平台叠层预览门

最终 MP4 交付前，从最终编码文件重新抽取：第 1 帧、每页中点、每个切点后 1 帧和末帧。把这些帧按 [平台叠层参考](../assets/references/platform-overlay-reference.webp) 的遮挡关系检查，或在目标平台的草稿预览中检查。

以下任一项直接失败：

- 白色正文、关键数字、来源或页码与账号头像、发布标题、右侧按钮、评论入口重合；红色强调行允许与左侧账号 Logo 轻微重叠，但被遮挡超过 25% 或语义无法完整阅读仍失败；
- 为避让平台 UI 把正文缩到手机端难以阅读；
- 正文越出白字/红字安全框，进入平台右侧保留区（锁定 JSON `platform` 段，来源行除外），或板块边界偏离锁定 JSON 超过容差（config.json `layout.tolerance_px`）；
- 平台预览后才发现文字被挡，却仍将文件标记为最终版。

平台界面可能变化；如果用户提供了新的平台截图，以新截图测量覆盖范围并扩大保留区，不能缩小本文件的默认安全区而不做实际预览。
