# 封面与平台安全布局 V2

本文件用于制作封面、正文信息卡和发布前平台预览。用户没有明确指定其他版式时，必须执行本文件；用户只改变其中一项时，其他参数保持不变。

## 1. 固定参考资产

- [四角框与暗化层](../assets/references/cover-frame-overlay-v2.png)：1080×1920 RGBA，可直接作为封面叠加层使用；非透明区域约为 `x=0–1079, y=237–1682`。
- [封面文字位置参考](../assets/references/cover-text-layout-v2.png)：1080×1920 RGBA，只用于测量字号、位置、颜色、描边和两行关系；示例文字不得直接带入新闻封面。
- [封面缩略图正反例](../assets/references/cover-grid-good-bad-reference.jpg)：上排两张是通过样式，下排两张是失败样式。只观察字数、字号、层级和缩略图可读性，不复制其中新闻事实。
- [平台叠层参考](../assets/references/platform-overlay-reference.webp)：用于观察账号头像、发布标题、右侧操作栏和底部输入栏对视频的遮挡；其界面文字不是新闻内容。

## 2. 封面文案不是新闻长标题

封面承担缩略图点击识别，不复述完整报道标题。先从事实标题中提炼两层信息：

- `cover_headline`：主体或最强事件钩子，理想 4–7 个全角字宽，硬上限 8。
- `cover_subline`：结果、场景或第二信息点，理想 5–10 个全角字宽，硬上限 12。
- 两行合计硬上限 18 个全角字宽；同一事实不得在两行重复。
- 汉字和全角符号计 1；ASCII 字母或数字计 0.55；半角标点计 0.5。计数只是预筛，最终必须以实际字体测量宽度为准。
- 主标题不写完整日期、来源名称和“发布/宣布/回应称”等弱信息前缀，除非日期本身就是新闻钩子。
- 禁止通过减小字号容纳长文案。超过宽度时必须重新压缩文案。

通过示例：

```text
苹果新CEO
首场发布会

机器人闪电
百米8秒94再破纪录
```

失败示例：

```text
小鹏机器人融资超9亿美元
腾讯、阿里参与战略投资

小米玄戒三芯齐发
手机到智驾全栈AI算力
```

失败原因不是事实错误，而是字数过多迫使字号缩小，在双列信息流中失去第一视觉层级。

## 3. 封面合成顺序

画布固定为 1080×1920，合成顺序不可颠倒：

1. 从已下载视频选择与事件直接相关的干净帧。
2. 先裁掉源画面内部黑边、标题、字幕、日期条、账号贴纸和说明文字。
3. 将有效画面按 `cover` 等比例铺满 `x=0, y=240, w=1080, h=1440`，根据主体移动焦点；不得拉伸。
4. 将 `cover-frame-overlay-v2.png` 以 1080×1920 原尺寸叠加在 `x=0, y=0`，不得缩放、裁切或重绘成近似版本。
5. 按本文件固定参数重新排版当前新闻的 `cover_headline` 和 `cover_subline`。`cover-text-layout-v2.png` 只能用于比对，不得直接叠加示例文字。
6. 导出独立 `cover.png`，再把它作为最终视频的第 0 帧。

禁止在封面出现：

- 新闻主播、演播室口播者、AI 播报人员；
- 源视频自带的任何可辨识标题、字幕、日期、账号贴纸或水印式说明；
- “资料画面”“素材：抖音@xxx”等素材说明；
- 第三方概念渲染、专利图或未确认真机；
- 与正文不同的产品、人物或事件。

企业高管、当事人或事件主体本人可以出现，但必须是新闻主体，而不是负责播报新闻的人。

## 4. 封面固定排版

- 主标题：微软雅黑粗体 `144px`，行高 `158px`，颜色 `#0AEAE6`，水平居中；文字可见包围盒参考 `y=1140–1250`，安全宽度 `x=80–1000`；黑色描边 5–6px 或等效硬阴影。
- 副标题：微软雅黑粗体 `112px`，行高 `128px`，白色，水平居中；文字可见包围盒参考 `y=1309–1405`，安全宽度 `x=54–1026`；黑色描边 4–5px 或等效硬阴影。
- 主副标题必须各占一行，禁止换行、横向压缩、非等比缩放和自动缩字。
- 两行标题的视觉中心与参考资产一致。主体面部、产品核心部件或关键动作不得被标题遮住；构图冲突时换帧或移动背景焦点，不移动文字模板。
- 青色只能用于主标题；副标题保持白色。不要因为品牌色改成橙色、红色或其他颜色，除非用户当次明确要求。

## 5. 缩略图验收门

全尺寸封面通过不代表信息流缩略图通过。渲染全片前必须同时检查：

1. 完整 9:16 封面缩放到 270×480。
2. 中央 3:4 区域 `crop=1080:1440:0:240` 后缩放到 270×360，模拟双列信息流卡片。

在 270×360 预览中必须满足：

- 不放大图片也能立即读出两行文字；
- 主标题仍是第一视觉层级，宽度约占安全区域 55%–88%；
- 副标题清楚但不抢主标题；
- 两行均完整，没有触边、截字或缩成小字；
- 主体仍能被识别，文字没有压住主体关键部位；
- 四角框完整可见。

任一项失败即 `BLOCKED_VISUAL`，先改文案或换底图，不进入全片渲染。

## 6. 正文平台安全布局

平台叠层会覆盖底部账号、发布标题、操作栏和评论入口。默认 1080×1920 采用以下保守安全区：

```text
关键文字安全区：x=54–820, y=140–1300
右侧交互保留区：x=850–1080, y=700–1600
底部平台保留区：x=0–1080, y=1320–1920
```

右侧和底部保留区可以继续显示无文字的实拍画面或非关键信息，但不得放主副标题、正文、关键数字、页码或来源。

默认正文页 V2：

- 顶部标题区：黑底 `x=0, y=0, w=1080, h=360`，底部 3px 黄色分隔线。
- 主标题：微软雅黑粗体 64px、行高 78px、黄色，`x=60–1020`，可见顶部约 `y=145`，单行。
- 副标题条：`x=66, y=245, w=948, h=82`，黄色圆角矩形，圆角 22px；内部 46px 黑色粗体，单行。
- 实拍层：`x=0, y=360, w=1080, h=1560`，真实下载素材按 `cover` 铺满到画布底部。
- 正文信息卡：`x=36, y=860, w=804, h=430`，黑色或极深色，透明度 82%–90%，圆角 22px；不得延伸进入右侧交互保留区。
- 栏目角标：`x=54, y=884`，约 `124×41px`。
- 页码：放在信息卡右上角，右边界不超过 `x=812`。
- 分页正文：`x=54, y=960, w=744`，微软雅黑粗体 48px、固定行高 64px，最多 3 行；只强调一行或一个短语。
- 来源行：`x=54, y=1228, w=744`，微软雅黑 24px、行高 32px、灰色；只写事实来源，不写“素材：抖音@xxx”。

正文卡可以覆盖实拍层，但不能用大面积黑底把实拍画面压缩成很小的中间窗口。实拍层在正文卡以外应持续铺满，底部平台保留区不再放自制文字。

## 7. 平台叠层预览门

最终 MP4 交付前，从最终编码文件重新抽取：第 1 帧、每页中点、每个切点后 1 帧和末帧。把这些帧按 [平台叠层参考](../assets/references/platform-overlay-reference.webp) 的遮挡关系检查，或在目标平台的草稿预览中检查。

以下任一项直接失败：

- 正文、关键数字、来源或页码与账号头像、发布标题、右侧按钮、评论入口重合；
- 为避让平台 UI 把正文缩到手机端难以阅读；
- 正文卡进入 `x>850` 或关键文字进入 `y≥1320`；
- 平台预览后才发现文字被挡，却仍将文件标记为最终版。

平台界面可能变化；如果用户提供了新的平台截图，以新截图测量覆盖范围并扩大保留区，不能缩小本文件的默认安全区而不做实际预览。
