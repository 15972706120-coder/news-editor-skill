# 交付与版本规范

> **当前覆盖规则**：最终 MP4 必须按 [当前制作配置 V2](current-production-profile-v2.md) 与封面主标题同名，不再使用 `<标题>-<变体>.mp4`。

## 双目录硬约束

输出区与工作区物理分离，分别位于独立磁盘路径与项目根目录：

```text
<输出根>\                    # 用户输出区（独立磁盘，根目录见 config.json 的 output.root），只放最终交付
<项目根>\.news-editor-work\  # 内部工作区，保留全部可追溯资料
```

输出根必须保持“打开即可取成片”的状态；`.news-editor-work` 才是素材、工程、版本和验收记录的存放位置。不得把工作区放进输出区，也不得把最终交付只放在系统临时目录。

## 输出区结构

```text
<输出根>\
└─ YYYY-MM-DD/
   ├─ 1.封面主标题/
   │  ├─ 封面主标题.mp4
   │  └─ 封面.png
   ├─ 2.封面主标题/
   │  ├─ 封面主标题.mp4
   │  └─ 封面.png
   └─ 3.封面主标题/
      ├─ 封面主标题.mp4
      └─ 封面.png
```

硬性规则：

- 输出根目录只允许 `YYYY-MM-DD` 日期目录，不允许散落文件或其他目录。
- 日期使用北京时间的实际生产日期；日期下一层只允许新闻主题目录，不允许散落文件。
- 主题目录命名为 `N.<cover_title_canonical>`，`N` 按当日完成生产并输出的顺序从 1 连续递增；标题必须就是封面主标题。
- 一个主题目录默认恰好包含一个最终 MP4 和一个 `封面.png`，不得有子目录。
- 最终 MP4 固定为 `<cover_title_canonical>.mp4`；文件 basename 必须与主题目录去掉 `N.` 后完全一致，不带任何声音、时长或版本后缀。
- 只有用户明确需要时才可额外放入 `发布文案.txt`、`来源说明.md` 或 `配音.wav`。其他文件一律禁止。
- 脚本、源码、依赖、截图、测试素材、下载原片、接触表、预览帧、日志、缓存、QA 报告和历史版本不得进入输出区。

## 内部工作区结构

```text
.news-editor-work/
├─ YYYY-MM-DD/
│  └─ 1.中文新闻短名/
│     ├─ 素材/
│     ├─ 工程/
│     ├─ 音频/
│     ├─ 预览/
│     ├─ 验收/
│     ├─ 日志/
│     └─ 历史版本/
├─ 历史工程/
└─ 敏感文件/
```

- 下载原片只读保存在 `素材/`；Remotion、FFmpeg 脚本、源码和依赖放 `工程/`。
- 分页配音、BGM stem 和混音中间件放 `音频/`；抽帧、接触表和平台叠层图放 `预览/`；`qa-report.json` 与检查证据放 `验收/`。
- 浏览器 Cookie、profile、会话和临时签名信息不得写入输出区或公开交付文档，只能存放在受控的 `敏感文件/`。
- 当前制作的内部版本可包含时长、变体和 `vNN`；重新输出时把旧输出文件移到相应主题的 `历史版本/<时间戳>/`，再写入稳定输出名。

## 输出与目录检查

只有状态为 `FINAL_READY` 的主题才能输出。使用：

```powershell
pwsh scripts/publish_news_output.ps1 `
  -WorkRoot <项目根>/.news-editor-work `
  -Date YYYY-MM-DD `
  -Sequence 1 `
  -CoverTitle 封面主标题 `
  -FinalVideo <内部最终版.mp4> `
  -Cover <内部封面.png>
  # -OutputRoot 缺省从 config.json 的 output.root 读取

pwsh scripts/check_output_layout.ps1   # 输出根目录同样缺省从 config.json 读取
```

输出脚本先复制到临时文件再改为稳定文件名，避免留下半成品；目标已有内容时默认拒绝，只有明确使用 `-Replace` 才会把旧版归档后替换。目录检查失败时不得交付。

## 选题候选交付

用户未指定主题时，第一份交付为 `topic-scout.md`，至少包含：

- 5–8 个去重候选主题、完整原始信息标题及一句话摘要。
- 事件时间、非国家级来源或原始发布、可点击的核验链接和抖音素材线索。
- 时效性、公共价值、短视频表达力、素材条件和风险判断。
- Top 3 推荐及推荐理由。
- 已执行国家级媒体来源排除检查的说明。
- 明确的选择门：等待用户选择，或依据用户的明确授权代选后继续。

在此节点前不批量下载素材，不把尚未确认的候选当作正式制作主题。

## 素材清单交付

选题确认后，每个主题必须生成 `source-manifest.md`，记录：

- `canonical_source_title`：来自合格非国家级来源页面的完整原始信息标题。
- 实际使用的抖音查询词；首条查询应与原始标题一致，只允许清理标点和无信息量前后缀。
- 下载的 1–3 条抖音页面链接、账号、平台标题、本地文件名和媒体规格。
- 每个候选片段的 `subject_identity`、`footage_type`、`supports_claim`、`misleading_risk` 和 `original_text_regions`。
- 每条素材的候选/实际使用时间码、画面内容、原始文字区域、裁剪缩放位移参数、底部字幕模糊区域和授权边界。
- 多段拼接方案，包括同一素材的多个时间段或跨 1–3 条素材的镜头顺序。
- 被替换片段及原因，例如局部模糊后字幕仍可辨识、满幅后主体被截断、只有主播画面或内容不匹配。
- 不记录浏览器 profile 绝对路径、登录态有效期、Cookie、会话 ID、临时签名链接或其他运行时凭据。

`edit-plan.md` 必须逐镜头引用素材清单中的文件和时间码。成片中不得出现无法追溯到该清单的新闻主体画面。

## 内部版本命名

- 主题：使用能识别事件的短名称。
- 时长：使用 `9s`、`14s` 等明确标记。
- 变体只用于内部版本，例如 `MiniMax配音`、`无原声`、`封面版`；不得进入输出文件名。
- 版本：从 `v01` 递增；重大方向变化增加变体名。
- 草稿保留 `draft` 标识并放在草稿目录；`final/` 中的最终候选和最终版不得使用 `draft` 文件名。
- 输出区不额外维护多个别名，只保留一个稳定中文名最终文件；所有版本记录留在工作区。

## 节点状态汇报模板

每个关键节点用四项简报，不必为小修订机械生成文件：

1. **结果**：本节点完成了什么。
2. **证据**：时间码、媒体探针、预览帧或验收结果。
3. **交付**：本节点生成的文件。
4. **下一门槛**：继续前还要验证什么。

## 草稿交付

草稿应同时提供：

- 可播放 MP4。
- 至少一张代表性预览帧；涉及封面时必须含封面。
- 涉及封面时必须同时提供中央 3:4 裁切后的 270×360 双列缩略图；涉及正文排版时提供平台叠层预览。
- 本版变更摘要。
- 已知问题和下一步，不把未完成项描述为完成。
- 素材画面是否已裁除干扰文字或将底部字幕模糊至不可辨认、是否满幅覆盖中间内容区、封面是否为非主播镜头的明确检查结论。

## 最终交付

最终回复必须独立包含：

- “已完成”或明确的阻塞结论。
- 时长、分辨率、帧率、音轨等核心规格。
- 封面短标题、固定字号、缩略图和平台安全区是否通过的结论。
- 用户本轮要求对应的改动清单。
- 使用的 1–3 条抖音素材来源账号或链接，以及主体画面均来自下载素材的说明。
- 最终 MP4 与 `封面.png` 的绝对可点击链接。
- 独立配音、发布文案或来源说明只有在用户需要时才进入发布目录；工程和 QA 资料提供工作区链接，不复制到发布目录。
- 交付前明确报告目录检查结果；稳定 `<输出根>/YYYY-MM-DD/N.中文新闻短名/`（输出根见 config.json）中的文件才是主交付。

## 最终 QA 记录

`qa-report.json` 至少记录：

- 文件绝对路径、大小和修改时间。
- 容器时长、视频编码、宽高、帧率。
- 视频流时长、音频流时长、实际解码帧数、预期帧数、逐页帧数列表及总帧数公式。
- 音频编码、采样率、声道。
- 最终编码 MP4 的综合响度和真峰值；逐页人声与 BGM 重叠区间的响度差。
- 自动检查是否通过。
- 已人工查看的帧号。
- 已人工试听的区间。
- 实际使用的源文件与时间码。
- 每个镜头的主体身份、画面类型、支持正文和误导风险检查结果。
- 每个源片段开头/中间/结尾的可辨识原始文字残留检查结果。
- 底部字幕局部模糊的时间段、像素区域、全程不可读和不遮挡主体的检查结果。
- 中间内容区黑边、黑带、空白和整幅模糊补边检查结果。
- 自生成主体画面数量，必须为 0。
- 封面主播/主持人/演播室口播人物检查结果，必须为 0。
- 封面第三方渲染、专利图、源文字和无关主体检查结果，必须均为 0。
- 封面主副标题的实际文案、全角字宽、144px/112px 固定字号、四角框资产和 270×360 缩略图检查结果。
- 正文关键文字包围盒、平台右侧/底部保留区参数、平台叠层预览帧号和遮挡检查结果。
- G0–G8 每一门的状态、失败证据与最终状态；只有 `FINAL_READY` 可作为最终交付。
- 仍存在但用户接受的限制。

自动检查的数值必须由实际命令输出写入，不得根据目标时长反推帧数或手工填写目标响度。视觉检查必须记录实际查看的最终成片帧号；亮度或颜色像素统计不能单独证明无原始文字、无黑边或素材身份正确。
