# 支付宝内容创作平台发布管线（手机通讯生活）

> 版本：1.0
> 适用环境：Windows 11、用户日常 Chrome、`computer-use` 桌面自动化
> 适用流程：用户验收成片 → 明确发布指令 → 平台上传 → 封面/声明 → 批量或单条发布 → 发布后核验
> 本文依据 2026-09-14 双视频（打了21个耳洞、女孩硬拉140公斤）实跑流程整理，可直接作为其他 Agent 的执行规范。

## 1. 触发条件与授权边界

本管线只在用户对已交付成片发出**明确发布指令**后启动，例如"内容没问题，请帮我发布""发布到手机通讯生活""把今天几条发出去"。含糊表态（"看起来不错"）不构成发布授权。

- 发布对象是 config `output` 段定义的输出区中、用户已验收的最终 MP4（文件名 = `cover_title_full`，见 config `output.cover_title_full_pattern`）及其所在主题目录。
- 发布是**不可逆对外行为**：只发布用户点名的条目；用户点名"今天这批"时，发布该日期目录下全部通过验收的主题，发布前列出清单让用户可打断。
- 未获明确指令不得上传；登录只依赖用户浏览器内置的密码管理器自动填充，Agent 不索取、不键入、不回传账号密码与验证码。

## 2. 环境选择（硬性约束）

必须用 `computer-use` 驱动**用户日常 Chrome（真实配置文件）**，禁止 agent-browser 或其他独立自动化浏览器实例。理由：

1. 支付宝登录凭据只存在于用户 Chrome 的密码管理器；干净实例没有凭据，也没有短信验证码通道，登录会直接卡死。
2. 蚂蚁系站点风控对自动化浏览器特征（CDP、`navigator.webdriver`、全新指纹）敏感；用真实环境发布行为最不容易触发滑块、短信校验或账号限流。
3. 上传流程包含 Windows 原生文件对话框，属于"网页 + 系统对话框"混合流程，computer-use 可全程覆盖。

Chrome 未运行时，启动器按名称可能找不到它，直接用完整路径启动（`C:\Program Files\Google\Chrome\Application\chrome.exe` + 发布页 URL，见 config `platform_publish.publish_url`）。

## 3. 入口与会话

1. 直接打开发布页 URL（config `platform_publish.publish_url`，含 appId）。会话有效时直接落在「短视频创作」页；标题栏出现「支付宝内容创作平台」即认为入口正确。
2. 会话过期会 302 到 `auth.alipay.com` 登录页，默认显示二维码。切换到「账户登录」标签（注意该页标签为 账户登录/扫码登录/验证码登录，"密码登录"并非标签名），点击账号输入框后 Chrome 密码管理器自动填充账号与密码，点「登录」。
3. 登录后若出现身份/账号选择，选择「手机通讯生活」；发布页 URL 中的 appId 即该生活号，核实页面左上角账号名一致后才继续。
4. 登录态过期是常态而非异常；每次发布运行都预期可能重新登录一次。

## 4. 上传视频

1. 在短视频创作页点击「点击上传」（或「拖或上传」区域）。
2. 原生文件对话框打开。**对话框属于独立的 Chrome 子进程（pid 不同于主窗口）**，点击其控件前先激活该 pid。
3. 视频路径含中文，不要逐字键入：把完整路径写入剪贴板 → 点击「文件名」输入框 → `Ctrl+V` → `Enter`。直接回车会打开文件；有时点「打开(O)」按钮只会进入目录，回车更可靠。
4. 也可先在对话框中手动导航到 config `output.root` 下的日期目录再双击文件，两种方式等价；完整路径粘贴更快。

## 5. 就绪门（最关键的一步）

**每条视频必须等左侧缩略图上的上传进度标记消失（100%）、右侧手机预览可播放后，才能进行后续步骤或批量发布。**

实跑证据：2026-09-14 双视频批量发布中，一条未完全就绪的条目被平台**静默丢弃**——无任何报错弹窗，不在「已发布/审核中/审核未通过/封面待优化/草稿箱」任何标签中出现，创作页草稿队列也清空，只能整体重传。发布脚本没有兜底，就绪门是唯一防线。

就绪的辅助判据：封面推荐帧（封面图片推荐）已生成、右侧预览能加载出视频画面、缩略图显示为视频画面而非进度环。

## 6. 标题与封面

- **标题描述**：平台自动用文件名填充，即 `cover_title_full`（主标题+全角逗号+副标题），直接保留，除非用户明确给出别的标题。确认字数计数未超限。
- **封面**：点击封面占位框（"上传封面"格子）→ 弹窗保持默认「截取封面」标签 → 直接点「完成」，采用**视频首帧**。成片首帧即制作时的标题卡，就是封面本身；**不要**切到「上传封面」标签单独传图片文件——那会多一次原生文件对话框，是整条管线里最脆弱的环节，而且没有收益。
- 弹出浏览器位置权限等无关弹窗时点「一律不允许」/关闭，不阻塞主流程。

## 7. 多视频批量流程

1. 第一条就绪后点左侧「+ 添加视频」加入下一条；每条重复第 4–6 节。
2. **作者声明**：点右上「批量编辑」（批量操作）→ 作者声明选第一项 → 「确定」，统一应用到全部条目。单条页面底部的「作者声明」区第一项为"内容无需标注"，批量弹窗第一项语义相同（原创无需特别标注），按第一项执行即可。
3. **发布前检查门**：逐条确认左侧每个缩略图都没有进度标记。任何一条未就绪就点发布，该条会被静默丢弃（见第 5 节）。
4. 点「批量发布」→ 弹窗确认全部条目勾选 → 「开始发布」→ 等待进度环 N/N 全部变绿、出现"发布完成"，页面随后自动跳转「内容管理」。

## 8. 单视频流程

队列中只有一条时，页面不出现「批量发布」按钮：

1. 滚动到页面底部，确认「发布时间」为「立即发布」（默认已选）、「可见范围」为公开。
2. 作者声明在页面「作者声明」区直接点第一项。
3. 点「确认发布」。页面跳转「内容管理」即发布动作已完成。

## 9. 发布后核验（必做）

1. 发布成功后页面自动进入「内容管理 → 已发布」。**以该列表为准判定成败**，不以发布弹窗消失或跳页为准。
2. 逐条按标题 + 当天时间戳核对每一条目标视频；一条都不少才算完成。
3. 某条缺失时依次检查「审核中 → 审核未通过 → 封面待优化 → 草稿箱」。审核中/待优化属平台侧状态，如实报告用户；审核未通过需读出违规原因。
4. 全部标签都没有、且创作页草稿也没有 → 该条发布被静默丢弃 → **重新上传补发**；此时队列只有这一条，走第 8 节单视频「确认发布」流程。
5. 补发同样要过第 5 节就绪门；重传后封面与声明需重新设置。

## 10. 环境障碍处理手册

- **焦点抢占**：用户可能同时在用其他应用（如 Workbuddy）。视觉点击前先 `open_application(activate=true)` 激活 Chrome；整屏截图截到的是前台窗口，被遮挡时改用无障碍树读取状态。
- **帧过期拒绝**：点击报 "frame is stale" 时不要重试旧帧，重新激活 + 重新截图 + 用新帧坐标点击。
- **无障碍按压失效**：网页自绘标签页（如内容管理的状态标签）对 AXPress 语义按压无响应，必须用真实坐标点击；原生按钮（如「点击上传」）AXPress 有效。
- **文件对话框独立进程**：对话框的 pid 与 Chrome 主窗口不同，点击其控件前先按该 pid 激活。
- **键盘输入**：Windows 上键盘事件要求目标窗口前台；粘贴路径前后不要插入会抢焦点的操作。
- **发布中途被打断**：以「内容管理」列表为唯一事实源重新盘点，缺哪条补哪条，不盲目整批重发。

## 11. 记录与交付

向用户报告时逐条给出：标题、发布时间戳（内容管理列表显示的时间）、平台与账号、以及（如适用）审核状态。批量发布部分成功时明确说明哪条失败、原因判断与补发结果。
